# DDA - osu! Danmaku Dodger

osu! の `.osz` を読み込み、譜面のヒットオブジェクトから弾幕を発射する避けゲーム(Godot 4)。
**ゲージ制**: 弾に当たっている間は継続ダメージを受けます。満タンは 250ms ぶんの被弾で、ゲージ 20% 以下では被ダメージが半分になります(連続して当たり続けると約 300ms でゲージ 0 = ゲームオーバー)。当たっていないときは毎秒 1.5% だけ回復します。MOD「練習」を付けるとゲージが 0 でも続行します(ベーススコア ×0.5)。

**ダメージの測り方(速く動いて抜けても減らない)**: ダメージは「弾に触れていた時間」で決まりますが、速く動いて弾を抜けると触れている時間が短くなり、実質的にダメージを減らせてしまいます(マウスは速度に上限がないので、特に有利でした)。そこで、1 ステップごとに「触れていた時間」と「**自機の経路が弾の当たり判定の中を通った長さ ÷ 基準速度**(キーボードの最高速 380px/s。`GameSim.CONTACT_SPEED_REF`)」の**長いほう**を、ダメージの時間として使います(`BulletField.hit_dist`)。基準速度以下の動き(止まっている・通常の移動・低速)は、これまでと同じです。基準速度より速く抜けたときは、キーボードの最高速で同じ距離を抜けるのと同じダメージになります(弾の幅 16px を抜けると、どんなに速くても約 17%)。弾の速さには影響されません(止まっている自機に弾が通り過ぎるときは、触れていた時間のまま)。HUD とリザルトには、実際の触れていた時間(被弾時間)ではなく、**ダメージ量**(ゲージ満タン = 100%。回復は引かない。協力のリザルトの個人別の欄は、自分ひとりぶん)を出します。協力の参加者は、触れていた時間と、速く動いたぶんの追加ダメージに分けてホストへ送ります(通信の形式は変わりません)。確認は `tests/test_contact_dist.gd`。

## 起動と画面の流れ
`run.bat` をダブルクリック、または `godot --path .`。起動するとまず**タイトル画面**が開きます(下記)。
曲(`.osz`)は、プロジェクト直下 / `songs/` / 実行ファイルの隣(と、その `songs/`)/ ユーザーデータ内の `songs/` に置くと一覧に出ます。**同じ曲は 1 つにまとめます**(パスの書き方の違い・大文字小文字の違い・別の置き場にある同じ名前と大きさのコピー・名前が違っても譜面の中身が同じもの)。読めなかった .osz は、選曲画面の下に名前を出します。**ウィンドウに `.osz` をドラッグ&ドロップ**するか、選曲画面の「.osz を開く…」でも追加できます(osu!standard のみ対応)。ドロップは**どの画面でも**使え、**複数のファイルを一度に**入れられます。取り込んだ曲はユーザーデータの `songs` にコピーされる(次の起動でも残る)ので、元のファイルを消しても大丈夫です。選曲画面では、画面を作り直さずに一覧へ加わり、最後の曲が選ばれます。プレイ中とロビーでは、取り込みと通知だけです。ドロップを受け取った瞬間に、画面の真ん中から水色の輪が広がります(Godot には「ファイルをドラッグして窓に入った」ことを知る仕組みがなく、アプリが知るのはドロップされた瞬間だけです)。**曲を選んだときの弾幕は、一度作ったら直近 10 曲ぶんを覚えておく**ので(MOD 適用前のものを持つので、MOD を変えても使えます。ファイルが差し替わると作り直します)、同じ曲に戻るときは速く読めます。難易度ごとの生成は並列に行います。

### タイトル画面
「**プレイ / マルチプレイ / 遊び方 / 設定 / 終了**」の 5 項目(↑↓ + Enter、またはマウス)。
- **プレイ** → 選曲画面(選曲画面の Esc / 「タイトル」ボタンでタイトルへ戻れます)。
- **マルチプレイ** → 部屋を作る / 招待コードで入る(下記「マルチプレイ」)。
- **遊び方** → 遊び方パネル(はじめに / 操作 / ゲージとスコア / MOD / マルチプレイ / 曲の追加)。**説明文はゲーム中の画面には出さず、すべてここに集めています**(「曲の追加」には songs フォルダを開くボタンがあります)。
- **設定** → 設定パネル(操作 / 音 / 画面 / その他)。MOD は設定ではなく、難易度選択画面の **MOD ボタン**(M キー)から選びます。
- **終了** → 「ゲームを終了しますか？」の確認(Enter で終了、Esc・キャンセル・パネルの外のクリックで戻る)。**タイトル画面で Esc を押しても、同じ確認が出ます**。全画面のときはウィンドウの ✕ が見えないため、ここから終了できます(`scripts/ui/quit_panel.gd`)。
- 背景と曲: タイトルでは、**ランダムに選んだ曲**(と、その中のランダムな譜面)の背景画像を出し、その曲を流します(プレビューの位置から、ふわっと入る)。曲が終わると、別のランダムな曲へ(背景はクロスフェード)。遊び方・設定を開いても曲は流れ続け、「プレイ」で小さくなって止まります。曲が 1 つもないときは、無音で暗い背景のままです。
- 版の表示: 左に **BETA v0.6.0**(`project.godot` の `config/version` から)。新しいバージョンがあるときの案内は、その右隣に出ます(項目のカードには重ならない)。
- 画面に操作の説明・キーの案内・注意書きなどは出しません(ゲーム中の HUD・ポーズ・リザルト・選曲・設定とも)。データの表示(Lv・スコア・内訳・MOD の効果など)は残しています。リザルトの下には、キー案内の文字ではなく「リトライ」「メニューへ」のボタンがあります(右下に主ボタンの「メニューへ」、その左に「リトライ」。Enter / R でも同じ。ボタンは、現れるまでの約 1.6 秒はクリックできない)。

## 画面と操作
**操作はマウスが主、キーボードは補助**として配置を決めています。どの画面も同じ決まりです。
- **戻る = 左上**(`◀ …`)/ **設定 = 右上** / **決定(主ボタン)= 右下**(アクセント色の塗り。`UiStyle.style_primary`)。
- **パネル**(MOD・設定・遊び方・アップデート・終了などの確認)は、**右上の「✕」、パネルの外のクリック、Esc** のどれでも閉じます(`UiStyle.close_button` / `close_on_outside_click`)。ポーズだけは、誤クリックで再開して被弾しないよう、外のクリックでは閉じません。アップデートのダウンロード中も閉じません。
- **F11** で全画面とウィンドウを切り替えられます(プレイ中は無効、ポーズ中は有効。設定にも保存)。

### 選曲画面
左に曲、右に難易度カード(大きな Lv・本家★の推定・弾数バー。MOD を付けると適用後の Lv と「MODなし」の値)。選択中の難易度の詳細(弾速・弾径・弾数・長さ)は下の帯に出ます。**流れは 曲(左)→ 難易度(右)→ PLAY(右下)の一方向**で、左上に「戻る」、右上に「設定」、下の段は左に「MOD」と付けた MOD のチップ、右に「PLAY」です(マルチプレイの曲選びでは「決定」)。曲を移ったときは、**前に選んでいた難易度に Lv がいちばん近い難易度**が選ばれます。曲を読み込んでいる間は、難易度の一覧が薄くなって「読み込み中…」と出て、PLAY は押せません。曲が 1 つもないときは、右側に「曲がありません」と、「.osz を開く…」「曲フォルダを開く」のボタンが出ます。読み込めなかった曲のメッセージは、難易度の詳細の下に赤い文字で出ます。

| キー | 動作 |
|---|---|
| ↑ ↓ | 曲を選ぶ |
| ← → | 難易度を選ぶ(左が易しく、右が難しい。端で止まる) |
| Enter | 開始(難易度カードのダブルクリックでも開始) |
| M | MOD を選ぶ |
| O | 設定パネルを開く。Esc / O で閉じる |
| Esc | タイトルへ戻る |
プレイ後(リザルトからメニュー、ポーズからメニュー)に選曲画面へ戻ったときは、**直前にプレイした曲と難易度が選ばれた状態**で開きます(設定の `last_song` / `last_diff` に保存するので、次に起動したときも同じです)。

### 画面の動きと触り心地
すべてなめらかに動くだけで、**点滅・フラッシュ・画面揺れはありません**(動きは、行き過ぎて 1 回戻るだけの弾み)。「触って気持ちいい」ことを重視して、動きと音の両方で反応を返します。
- **すべてのボタン・スライダー**(`scripts/ui/juice.gd`が、ツリーに入ったものへ自動でつけます): ホバーで弾むように少し大きくなり(小さな音つき)、押すとぎゅっと縮んでクリック音、離すと行き過ぎてから戻る。スライダーは動かすたびに、値に応じた音程の小さな音が鳴る(音階になる)。外したいノードには `set_meta("no_juice", true)`、クリック音の種類は `set_meta("juice_sound", "confirm")` で変えられます。
- **UI の効果音**(`scripts/ui/ui_sfx.gd`。`assets/sfx` のファイルを読む。音は下の「効果音」の音作りツールで作った): ホバー / クリック / 選択(音程が上下する)/ 決定 / 戻る / パネルの開閉 / トグルの入切 / 数字のカウント / ランクのスタンプ / 画面切り替えの風切り音 / 通知 / 拒否。音量は「効果音」に従い、設定の「音」にある **「UI の音」** で切れます(`ui_sound`)。
- **画面の切り替え**(`scripts/ui/screen_wipe.gd`): 体力バーと同じ向きの斜めの幕が左から画面を覆い、入れ替えたあと右へ抜けます。縁を水色の細い線が走り、風切り音がつきます。
- **マウスカーソル**: 動いた跡が短い尾になって薄れ、押したところから輪と数粒が広がります(`ui_fx.gd`)。
- タイトル画面: ロゴが 1 文字ずつ上から弾んで落ち、入場後はゆっくり浮き沈みする。選択の枠は項目の間を弾みながら滑り(動くあいだ少し縦に伸びる)、音階のような選択音が鳴る。背景はマウスと逆へ、漂うリングは同じ向きへ、ゆっくり追従して動く(奥行きの視差。選曲・マルチプレイの画面も同じ)。「プレイ」を決めると輪と粒が広がり、項目が左へ流れ出る。
- 選曲画面: 背景の画像が曲ごとにクロスフェードし、ゆっくり拡大・縮小し続ける。曲・難易度のカードは順に滑り込み、選択中(ホバー中)のカードは弾みながら少し右に出る。カードは押すと少し縮み、離すと弾んで戻る。曲・難易度を移るたびに音階が上がる・下がる。Lv は 0 から(MOD を切り替えたときは前の値から)数え上がり、弾数バーは左から伸びる。MOD のチップは弾んで現れる。スクロールの目盛りごとに小さな音。
- OPTIONS・MOD・遊び方・アップデート: 背景が暗くなり、パネルが中心から弾んで現れる(開く・閉じる音つき)。項目が上から順に現れ、選択の枠が項目の間を滑る。セクションを切り替えると、ページが進む向きから滑り込む。トグルは押すと弾み、入れたときは粒が弾ける。スライダーの値の文字は変わるたびに跳ねる。
- ポーズ: パネルが弾んで現れ、ボタンが上から順に現れる。↑↓ で選んだボタンが弾む。
- 音量メーター・通知: 上 / 下から弾んで出入りする。ホイールで音量を変えると、その音量での小さな音が鳴る。
- マルチプレイのロビー: パネルが左右から滑り込む。参加者が入ると弾んで現れ、音が鳴る(出ると別の音)。
- **PLAY からゲーム開始までの「間」**: PLAY を押すとすぐには切り替えず(0.4 秒)、選んだ難易度のカードが前に出て、ほかが退き、背景がズームインして、曲が小さくなる(PLAY ボタンから輪と粒が広がる)。そのあと斜めの幕で切り替わる。ゲーム画面では、**メニューで見ていたカーソルが、自機の開始位置へ弧を描いて飛び**(0.6 秒。輪がしぼんでいく)、着いた瞬間にその場で自機が弾んで現れる。着くまでマウスは自機に効かず、着いたら OS のポインタも自機の位置へ移してからマウスを捕まえる(マウス操作で、カーソルがそのまま自機になる / ポーズでカーソルが戻るときも自機の場所から出る)。キーボード操作のときは、少し待って自機が現れる。曲が始まる瞬間に READY が「GO」に変わって消える(READY の長さ 1.5 秒は変えていないので、曲のタイミングは従来どおり)。
- プレイ中: 左右のパネルが外から滑り込み、READY が弾んで現れて消える。グレイズの数字は増えると弾み、被弾中はダメージ量の数字とアリーナの枠が赤くなる。スキップ案内は下からせり上がって出入りする。クリア時は背景だけ残して他がフェードアウトし、同じ背景のままリザルトへ移る。休憩に入って弾が抜けると、中央にカウントダウン(小数 2 桁+バー)がふわっと出る。
- リザルト: 左のパネルと右の列、下の体力グラフが滑り込む。**ランクの周りの円状のメーターが、真上から時計回りに最終スコアまで伸び**(ベーススコア = 100%。MOD で変わるベーススコアに合わせる)、スコアの数字と達成率(%)が一緒に数え上がる。伸びきったら**ランク文字が大きいところから叩きつけられる**(着地で衝撃波の輪が 2 つと粒が広がり、パネルがずんと沈み、低い音とベルが鳴る)。メーターは **F / D(40%) / C(55%) / B(70%) / A(85%) / S(95%)** の範囲を色分けし、境目に目盛りとランクの文字・そのランクになる点数(例: 950k)を出す(ノーミスは範囲に関係なく SS)。ゲームオーバーのときは、色分けなしで到達度まで伸びる。右上にはスコアと内訳(ベーススコア・グレイズボーナス・被ダメージ係数)、GRAZE・**被弾回数・ダメージ量**。下には**体力の推移のグラフ**(横: 曲の時刻、縦: 体力 0〜100%。20% の低体力ライン・休憩地帯の帯・被弾した時刻の印つき。線の色は体力に応じて変わり、ゲームオーバーは終わりに赤い点。左から右へ描かれる)。マルチプレイは、右に参加者の成績の一覧(対戦: 順位・スコア・ランク・被弾回数/ダメージ量、WIN。協力: 1 人ずつの GRAZE・被弾)、グラフには対戦なら参加者の体力を色分けして重ね(最終成績といっしょに間引いた体力 48 点を送る)、協力はチーム共通の体力 1 本を出します。
- 開発用: `--smoke-start [keyboard] [--shots <接頭辞>]` で、PLAY を押してからゲームが始まるまで(発進 → カーソルの飛行 → 自機の出現 → GO)を、時間を追って確認できる。`--shot-anim <menu|options|result|title> <接頭辞>` で、開いてからの経過時間ごと(既定は 0.1〜2.5 秒)のスクリーンショットを撮れる(`t=0.7,0.8` のように撮る時刻も指定できる)。`--shot` は動きを待たず最終状態で撮る。指定の `.osz` が環境になければ、見つかった最初の曲を使う。

### OPTIONS(設定パネル)
操作 / 音 / 画面 / その他 の 4 セクション(Tab で切替)。**使う順に並べています**。
- **操作**: 「マウス」(標準)が先頭、「キーボード」はその次。マウス感度の行は、マウスのときだけ有効で、キーボードのときは薄くなります。
- **音**: 全体音量 → 音楽 → 効果音(ホイールのメーター・ポーズと同じ名前と並び)、そのあとに **オフセット**(音と弾のズレの校正。値のあとに「弾が遅れる / 弾が早まる」と出る)、「UI の音」。
- **画面**: **解像度(ウィンドウの大きさ)**が先頭(1280×720 / 1600×900 / 1920×1080 / 2560×1440 / 全画面。画面に入らない大きさは選べない。選ぶと画面の中央に置き、設定に保存して次の起動でも使う)。そのあとに**垂直同期**(入り切り。切ると遅延が少し減る)と **FPS の表示**(画面の右下に、描画と処理の FPS を出す。プレイ中は、弾の判定の計算回数「判定 /s」も出る。F3 キーでも一時的に切り替えられる。`scripts/ui/fps_overlay.gd`)。**ウィンドウの枠をドラッグして好きな大きさにする機能は、これまでどおり使えます**(縦横の比は保たれ、余白は黒くなります。枠のドラッグで変えた大きさは保存しません)。F11 の全画面の入り切りも、ここに保存されます。
- **その他**: 起動時の更新の確認と、見つけたときの**自動更新**、**弾速の実験に参加する**(下記「弾速の実験」。標準は切)、(書き出した版では)「プログラムから開く」への追加。
設定は閉じるときに保存されます。

### MOD(難易度選択画面)
難易度選択画面の下の **MOD ボタン**(M キー)で開く専用のパネルで選びます(設定パネルからは切り離しました)。1 つ 1 枚のカードで(**6 枚がスクロールなしで収まります**。スコアの加算はタイトルの行の右端のチップ)効果とベーススコア加算を確認でき、パネルの下には、**MOD 適用後の難易度(Lv。値に応じた色)とベーススコアの倍率だけ**を大きく出します。切り替えるたびに、数字がなめらかに動き(0.5 秒)、Lv は動く間に色も変わります。選ぶたびに、後ろの難易度カードの Lv も測り直されます。下の段の左に「**すべて解除**」(何も付けていないときは押せない)、右下に「**閉じる**」(主ボタン)があります。右上の「✕」、パネルの外のクリック、Esc、M でも閉じます。パネルの上でホイールを回しても、後ろの曲・難易度の一覧は動きません。付けた MOD は、MOD ボタンの隣にチップで出ます。マルチプレイの曲選び(決定モード)でも同じです。

### ポーズ
Esc で開きます。**再開 / リトライ / メニューへ**(マルチプレイでは「退出」。リトライはなく、ゲームは止まらない)と、**全体音量 / 音楽 / 効果音**の 3 本のスライダーが、同じ見た目の 6 行で並びます。マウスを乗せた行が選択になり(アクセント色の枠)、キーなら ↑↓ で全部の行を選べて、Enter で実行、← → は**選んでいる音量の行だけ**を動かします(ボタンの行では何も起きません)。R でリトライ、Q でメニューへ。
**連続ポーズの悪用を防ぐ**(止めた弾をじっくり観察してから再開して避ける、を封じる): ① **ポーズ中は、アリーナ(弾・自機・危険エリア)を覆って見せません**(弾の描画も止める)。② 「再開」を押しても、すぐには動かしません。**自機だけを見せて(周りでゆっくり輪が広がる)、ゲームは止めたまま、使う人の操作を待ちます**(弾は見せない)。**マウスはクリック、キーボードは移動キー・Space・Enter** で動き出し、弾が **0.35 秒**かけて現れます(待ちの間の Esc は、ポーズへ戻る。待ちに入った直後 0.3 秒は、ダブルクリックでそのまま始まらないよう、操作を受けない。スキップの案内は、待ちの間は隠す)。③ 動き出してから **2 秒間は、またポーズできません**(Esc は無視され、拒否音が鳴る)。マルチプレイのメニューは、ゲームが止まらないので、これらの対象外です(`GameScreen.PAUSE_COOLDOWN` / `RESUME_VEIL` / `_resume_wait`)。
**プレイ中以外は、どの画面でも設定を開けます**(タイトル・選曲画面はそれぞれの入口 / 選曲画面は O キーでも、そのほかの画面は右上の「設定」ボタン)。パネルは `main.gd` が持ち、開いている間は下の画面はキー・クリックに反応しません。操作の標準は「マウス」です。

### 操作(開始前に OPTIONS で選択)
| モード | 移動 | 低速 |
|---|---|---|
| キーボード | 矢印 / WASD | Shift |
| マウス | カーソルを隠して相対移動(自機はカーソルの移動量どおりに動く。感度はメニューで調整) | Shift または右クリック(移動量が 0.3 倍) |

共通: **イントロのスキップ**(Space、または画面下の「スキップ」ボタン。最初のノーツの 1.5 秒前まで曲ごと進める。進む幅が 1 秒未満なら、ボタンも出ない。READY 中でも使える)。マウス操作のときは、スキップできる間だけマウスを捕まえず(カーソルが見えて、ボタンを押せる)、飛ばしたら(またはできなくなったら)自機の位置で捕まえ直します。**マルチプレイ**では、ボタンの中に押した人数(例: 「スキップ 1/2」)が出て、**全員が押したら、全員でいっせいに**飛ばします(ホストが人数を数えて配ります。途中で去った人は、数から外れます)。Esc でポーズ(↑↓ で項目、Enter で決定、R: リトライ、Q: メニュー、←→: 選択中の音量。マウスでも操作できる)。画面の切り替えには、斜めに走る短い幕(点滅なし)が入ります。当たり判定は自機中央の小さな赤い点です。

### 場所の偏りをなくす
旧版は、ノーツの位置(画面の中央に偏る)から全周リングを撃つので、弾の通過が中央に集中し(測定: 中央 130〜150 に対し隅 57〜75。平均 = 100)、隅や発生源から遠い場所は薄くなっていました(`tests/analyze_coverage.gd`)。
- **発生源の散らし**(`PatternGen.to_source`): 譜面全体のノーツ位置の分布を、x・y それぞれの累積分布(なめらかな曲線の表。階段にしない)で一様な位置へ写し、さらに端へ寄せます(`REMAP_EDGE`。f(u) = u − a/(2π)·sin(2πu) で、中央に折れ目ができません。中央から撃つ弾は中央を何度も通るので、発生源を一様にしても通過は中央に偏るため)。**スライダーの軌道は、形を変えず、頭の補正ぶんだけ平行移動します**(位置ごとに補正すると、曲線がカクカクの折れ線になるため)。譜面のノーツの並びはそのままに、隅・縁にも発生源が来ます。弾の通過密度は、平均 100 に対して 73〜128 になりました(旧: 57〜154)。`tests/test_special.gd` が、最小 0.55・最大 1.6 倍に収まることを確かめます。
- **曲がる弾**: clap の 3 重リングを、★に応じた角速度で曲げます(向きはリングごとに交互)。隙間の位置が時間で動くので、少しの移動では避けきれません。
- **協力の自機狙い**: 以前は、ホストが決めた 1 人(イベント番号 % 人数)だけを狙っていたので、イベント番号の偶奇などで特定の人に偏る(ある譜面で、2 人に 4 : 11)ことがありました。**全員を 1 発ずつ狙う**ようにしたので、1 人あたりの自機狙いの頻度は、ひとり・対戦と同じです。位置はホストが全員ぶんをまとめて配ります(`g_aim`)。対戦は、各自の画面で自分を狙う(以前のまま)。

## 実際の弾・自機の大きさ
表示する難易度(Lv)に対して体感が易しかったので、**弾の大きさを 1.25 倍、自機の大きさ(見た目と当たり判定)を 1.15 倍**にしています(`GameSim.BULLET_SIZE_MUL` / `PLAYER_SIZE_MUL`)。表示される Lv の数値は変えていないので、同じ Lv でも以前より難しくなります(Lv の計算の危険半径にはこの倍率を入れていますが、基準の大きさ DANGER_REF も同じ式で測るので、標準の大きさでの補正は 1 のままです。MOD の巨人・地獄や弾サイズの吸収で大きさが変わったときの比だけが、実際の当たり判定に合います。倍率の値は `PatternGen` が持ち、`GameSim` はそれを使います)。MOD の弾サイズ・自機サイズの倍率は、これに掛かります。ゲージの自然回復は毎秒 1.5% です。

## 危険エリア(デバフ)
少しかわすだけで同じ場所にとどまり続けられると、自機を大きく動かさずにクリアできてしまいます。これは、弾幕に譜面と無関係なものを足すのではなく、**盤面を 3×3 の 9 マスに分けて、小節ごとに危険エリアを決める**仕組みで止めます(`PatternGen._make_zones` が譜面から決め、`gen.zones` で渡します。`GameSim` が自機の位置で判定します)。
- **いつ**: 譜面の拍子と BPM から小節を数え(`PatternGen.measure_starts`)、約 16 秒(低難度)〜 9 秒(高難度)ぶんの小節(3〜8 小節)ごとに、新しい組み合わせが発動します。エリアは小節の頭に合わせて発動し、最後の 2 小節は休みで、次のエリアの**予告を 2 小節前から**出します。**最初の弾の発射前には、予告も出しません**(イントロをスキップできる間は、何も出ません)。
- **いくつ**: 1〜8 マス。★が高いほど多く(上限は 1 + 7×(★の度合い))、その区間のノーツの密度・キアイ・疑似乱数で ±します。1 譜面の中でも数は一定ではありません(例: Chimera は 4〜8 マス)。全マスが危険になることはなく、安全に残すマスのひとつは、その区間のノーツの重心のマスです(安全地帯が譜面の流れに沿って動きます)。
- **デバフ**(エリアごとに 1 種類。★が高いほど種類が増えます):

  | 種類 | 効果 | 出る難易度 |
  |---|---|---|
  | 鈍足(slow) | 移動が 0.45 倍(キーボードもマウスも) | すべて |
  | 脆弱(fragile) | 被ダメージが 2 倍 | すべて |
  | 毒(poison) | ゲージが毎秒 10% 減る(練習モードでは減らない) | 度合い 0.3 以上 |
  | 巨大(big) | 自機の当たり判定が 1.8 倍(中心の点も大きく描く) | 度合い 0.55 以上 |
- **見た目**(盤面・自機には文字を出しません。種類は色とマークで分かります: 鈍足 = 青・下向きの山形 / 脆弱 = 橙・割れた輪 / 毒 = 緑・しずく / 巨大 = 紫・広がる輪): **予告**は、点線の枠とマークが、フェードインで現れ、発動に近づくほど速く点滅します(1.5 Hz → 5 Hz。なめらかに明暗を行き来)。**発動**の瞬間に、白い枠が外へ広がって消え、そのあと、濃い面・実線の太い枠・はっきりしたマークになります(点滅は止まります)。終わる前にゆっくり消えます。受けている間は、自機の周りに、そのデバフの色の輪が出て、左のパネルに名前が出ます。
- 休憩地帯では効きません。難易度(Lv)の計算には入れていません。MOD の再生速度(加速)では、エリアの時刻も同じ割合で動きます。
- 協力: エリアは譜面から決まるので、全員で同じです。デバフは各自の自機が受け、脆弱・毒による追加ダメージは、被弾時間に換算してホストへ報告します(`g_ct` の `s`)。対戦は、各自のゲージ・スコアで計算します。
- 確認: `tests/test_zones.gd`(数が 1〜8・難易度で増える・小節の頭に合う・種類・各デバフの効き方・休憩/練習・協力の報告)。

## 難易度(DDA 難易度 v4)
このゲーム独自の指標です。**画面内にある弾の数(密度)**を軸に、弾速・弾サイズを補助項として測り、**本家の星と同じ目盛り**の Lv で表します。

1. 各弾が画面から出るまでの時間を計算し、0.1 秒ごとの「画面内の弾数 N(t)」を求める。**計測は「最初のノーツ(最初に弾を撃つイベント)」から「最後の発射」まで**で、曲頭のイントロは含めません(イントロの長さで難易度は変わりません)。
2. `score = 0.5 * 平均(N) + 0.5 * 上位5%点(N)`
3. `adj = score * (弾速 / 150)^1.25 * (危険半径 / 9.9)^1`(危険半径 = 実際の弾の当たり判定半径 + 実際の自機の当たり判定半径(上の 1.25 倍・1.15 倍を含む)。9.9 は弾サイズ 6.75 のときの危険半径。速い/大きい弾、大きい自機ほど adj が大きい。弾速の指数は、弾速が 2 倍だと画面内の弾数が約半分になる分を相殺した上で「速いほど難しい」にするため 1 を超えて 1.25 にしてある)
4. **長さ(持久力)の補正**: `adj` に `length_factor = clamp((T / 120)^0.15, 0.8, 1.3)` を掛ける(T = 手順 1 と同じ「最初のノーツ〜最後の発射」の秒数から、**休憩地帯と重なる時間を引いたもの**。弾の来ない休憩は持久力に数えない。MOD「加速」では休憩も 1/1.5 になる)。基準の 2 分で 1 倍、5 分で約 1.15 倍、75 秒で約 0.93 倍。密度が同じなら長い譜面ほど難しくなる(平均・上位 5% 点は長さに依存しないので、長さの効果はここだけ)。定数は `LENGTH_REF` / `LENGTH_EXP` / `LENGTH_MIN` / `LENGTH_MAX`。
5. `Lv = 補正後の adj を TARGET_TABLE(★→弾数の表)で逆引きした★換算値 − LEVEL_SHIFT(1.0)`(例: adj 80 → 表では 3.7 なので Lv 2.7、adj 165 → 5.9 なので Lv 4.9)。**Lv の目盛りを 1 だけ厳しくしてあります**: 同じ弾幕の Lv は、以前より約 1 小さく出ます。生成の目標も、その分だけ上の★の弾数に合わせるので(`target_score_for(★ + 1)`)、同じ Lv の弾幕は、以前より弾が多く難しくなります(Lv ≒ 推定★ は変わりません)。`Lv` の色の段階(`ui_style.gd` の `LEVEL_STOPS`)は、そのままです。

### 本家の星に近づける仕組み
- 基準として、本家の星評価を `scripts/osu/star_rating.gd` で推定する(サンプル 14 譜面の公式値と平均誤差 0.14★。他の曲での精度は未検証)。難易度そのものの定義には使わない。
- 目標の Lv は推定★そのもの。`pattern_gen.gd` の `TARGET_TABLE` で目標の弾数を決め、adj がそれに合うまで弾数の倍率を自動調整する。弾数は、その瞬間の局所ノーツ密度に比例する(曲の盛り上がりに沿って増減)。
- **弾の生成が合わせるのは、長さの補正を除いた密度だけ**です。長い譜面の弾数を減らして Lv を合わせることはしません。そのため Lv は、長い譜面では推定★より高く、短い譜面では低くなります(サンプル: Reol の約 75 秒の譜面は −0.1〜−0.5、Soleily(208 秒)は +0.1〜+0.3、Sound Chimera(297 秒)は +0.5〜+0.9)。
- 弾速は★に応じて ±15%(約 130〜175 px/s)だけ変える。微調整であり、効き方(`SPEED_EXP`)は実測が難しいので控えめな値。人間のプレイで確かめるための実験がある(下記「弾速の実験」)。
- 弾数を自動調整しても、弾数の下限/上限のせいで目標に届かない分は、弾サイズ(基準の 0.6〜1.4 倍)で吸収する。弾サイズの効き(`SIZE_EXP`)は簡易ボットの実験(弾サイズ 4 倍の幅 ≒ 弾数 2.5 倍の幅)から置いた値で、人間のプレイでは未検証。
- 自機狙いや弾種の変化は★に応じて解禁する。
- 長さの補正を除いた Lv は、サンプル譜面で推定★と ±0.1 以内で一致し、公式★との差は推定器の誤差(平均 0.14★)程度。長さの補正を含む Lv と公式★の順位相関は 0.95(`tests/test_rating.gd`)。
- MOD「加速」は曲が短くなる(実時間で 1/1.5)ので、長さの補正が少し下がります(Celsius' Extra: MODなし 5.33、加速 6.58)。

### 弾速の実験(人間のプレイで SPEED_EXP を確かめる)
Lv の計算は「弾が速いほど難しい」として弾速を `SPEED_EXP`(1.25)乗で効かせていますが、実測した値ではありません(ボットでは、同じ発射なら速い弾のほうが被弾が少なく、計算と逆でした。ただしボットは反応が速いので、人間とは違う可能性があります)。そこで、計算は今のまま、人間のプレイでデータを集めます(`scripts/speed_study.gd`)。
- 設定「その他」の **弾速の実験に参加する** を入れると、ひとりで遊ぶとき(弾幕に効く MOD なし。練習は可)、1 回ごとに次の条件のどれかで弾幕を作ります。プレイ中は条件を出しません。
  - **slow** 弾速 ×0.8 / **base** ふだんどおり / **fast** 弾速 ×1.25 … どれも**同じ Lv** に合わせる(弾数が自動で増減する)ので、計算が正しければ同じくらい難しいはず
  - **dense** 弾速はそのまま、目標の難易度 ×1.25(Lv が 1 段上)… 「難易度が 25% 上がると被弾がどれだけ増えるか」の物差し。fast と slow の差を `SPEED_EXP` の値に直すのに使う
- 条件は、譜面ごとに、遊んだ回数のいちばん少ないものを選びます(慣れの影響が条件に偏らないように)。選曲画面の Lv は変わりません(dense だけは結果画面の Lv が上がります)。
- 1 プレイごとに `user://speed_study.csv` に 1 行書きます(譜面・条件・弾速・Lv・被弾回数・ダメージ量・遊んだ時間・ゲームオーバーか など。外には送りません)。
- 集計: `godot --headless --path . --script tools/speed_study_report.gd`。条件ごとの「被弾 /分」と、fast / slow・dense / base の比、`SPEED_EXP` の推定を出します(4 条件をすべて遊んだ譜面が 5 つ以上、被弾の合計が 3 秒以上になるまでは推定を出しません)。fast / slow が 1 より大きければ、速い弾は計算より難しい(`SPEED_EXP` を上げる)、小さければ易しい(下げる)。

難易度(Lv・本家★の推定・MODなしの Lv)は小数点以下 2 位まで表示します。メニューの難易度リストは Lv の低い順に並び、括弧内に本家★の推定、平均/最大の弾数、弾速、弾径を表示します。
## スコア
**最終点 = (1,000,000 + グレイズボーナス) × 被ダメージ係数**

- グレイズボーナスは **30,000 点(3%)に漸近**します: `30,000 × (1 − exp(−グレイズ数 ÷ τ))`、τ = 発射イベント数 × 0.15(下限 10)。グレイズ数が τ で約 63%(18,964 点)、2τ で約 86%、3τ で約 95% と、増えるほど上乗せは小さくなり、無限にグレイズしても 30,000 点には届きません。MOD のベーススコア倍率はかかりません。
- 被ダメージ係数 = exp(−累計ダメージ ÷ τ)。1 から始まり **0 に漸近**します(0 にはなりません)。累計ダメージの単位はゲージ満タン = 1(= 250ms 相当の被弾)。回復しても、いったん下がった係数は戻りません。
- **τ は曲の長さに応じて伸びます**: `τ = 3.0 × max(弾が飛んでいる時間 ÷ 120 秒, 1)`。累計ダメージは長い曲ほど絶対値が大きくなるので、そのままでは長い曲が不利になるためです。「弾が飛んでいる時間」は、最初〜最後の発射の間から休憩地帯を除いたもの(難易度の測定区間と同じ起点)で、MOD で再生速度が変わったら実時間で数えます。120 秒以下の譜面の τ は 3.0 のままです。
  - 例(累計ダメージ 1.0 = 250ms の被弾 4 回ぶん、のときの係数): 短い譜面(τ 3.00)0.72 / Soleily Insane(弾が飛ぶ時間 191 秒、τ 4.77)0.81 / Laur の KoToreley's Echidna(235 秒、τ 5.88)0.84。なお τ の基本値は、減点が急すぎたので 2.0 から 3.0 にした(同じ被弾での係数が 0.61 → 0.72)

  | 被弾(満タンの 250ms 換算) | 累計ダメージ | 係数 |
  |---|---|---|
  | 100ms | 0.4 | 0.82 |
  | 250ms | 1.0 | 0.61 |
  | 500ms | 2.0 | 0.37 |
  | 1 秒 | 4.0 | 0.14 |

- **ゲームオーバーは常に 0 点(スコアなし)。** クリアしたときだけスコアが残ります。
- プレイ中の表示点数(整数は四捨五入。リザルトも同じ)は、その「クリアした場合の最終点」に**スコア進捗を掛けた値**です。スコア進捗 = **これまでに発射した弾数 ÷ 曲全体で発射する弾数**なので、弾が発射されるたびに、弾 1 発ぶんずつ増えます。最初のノーツまでのイントロと休憩地帯(休憩中の発射は数えません)では増えません。クリアした瞬間に最終点になります。被ダメージ係数は全体にかかるので、被弾するとその時点の表示点数も下がります。
- 表示される数字は、目標のスコアへ**イージング(ease-out)**で近づきます。発射のたびにカクッと跳ばず、滑らかにカウントアップします。
- **ランク**(クリア時): **SS = ノーミス(被弾 0 回)**。それ以外は「達成率 = 最終点 ÷ ベーススコア(MOD の倍率を含む)」で決まります: **S ≥ 0.95 / A ≥ 0.85 / B ≥ 0.70 / C ≥ 0.55 / D ≥ 0.40 / F それ未満**(`GameSim.RANK_TABLE`)。MOD の倍率を打ち消した率なので、練習(×0.5)や +11% などの MOD でランクは上下しません(達成率は被ダメージ係数 + グレイズのボーナス分)。ゲームオーバーはランクなし(`-`)。

### 休憩地帯
譜面データの休憩地帯(Break)の間は、**スコアの加点(グレイズ)とゲージの回復が無効**です(HUD に BREAK と表示)。ダメージは通常どおり受けます。

**弾の一掃とカウントダウン**: 休憩に入って、自機の周りが落ち着いた状態(下記)になったら、弾をすべて消します。そのときから休憩が終わるまでの残り秒を、フィールド中央に**小数点以下 2 桁**で表示し、下に残り時間のバーを出します(バーは残りが減るほど縮みます)。休憩中に新しく弾が撃たれたら、落ち着くまで待ち直します。

「落ち着いた」状態の判定(`BulletField.is_calm`): 次のような弾が**1 つもない**ことです。遠くにあって自機に向かっていない弾は、アリーナ内に残っていても無視します。
- **自機の近くにある弾**(自機の中心から `SAFE_NEAR_R` = 120px 以内。前の版の 320px より大幅に狭い)
- **自機に接近している弾**(今の向きのまま `SAFE_LOOK_T` = 3 秒以内に、自機から `SAFE_APPROACH_R` = 50px 以内〔自機・弾の当たり半径を含む〕を通る弾。旋回する弾は 0.2 秒刻みで先を調べます)
自機の脇を通る弾・遠ざかる弾・遠くで止まっている弾は、消滅の妨げになりません。

### クリア
最後の弾幕を撃ち終え(予兆も終わり)、自機の周りが上の意味で**落ち着いた状態**になったら、弾をすべて消して**クリア**です(固定の待ち時間はありません。弾が残り続ける場合の保険として、撃ち終えて `CLEAR_TIMEOUT` = 8 秒でクリア)。クリアしたら、**背景(曲の画像)だけを残して、アリーナ・自機・HUD・左右のパネルが 0.6 秒でなめらかにフェードアウト**し(プレイ画面は止めず、曲も止めません)、**そのままの背景でリザルト画面**に移ります。曲はリザルトでも流れ続け、メニューへ戻る/リトライで小さくなって消えます(曲が先に終わればそこで止まります)。ゲームオーバーの演出(曲が止まる・GAME OVER)は従来どおりです。

## MOD
メニューで、プレイ前に付けるかどうかを選びます(選択は保存されます。複数付けられます)。付けた MOD は HUD の右パネルとリザルトに表示されます。効果の定義は `scripts/mods.gd` の `ALL`(足すだけで、メニュー・HUD・リザルトに出ます)。

| MOD | 効果 | ベーススコア |
|---|---|---|
| 地獄 (HELL) | 弾サイズ +35% / 体力 150ms(ゲージ満タン = 150ms の被弾) / 低体力(20% 以下)の被ダメージ半減なし / **体力バーが 0.6 倍の長さ**(150ms ÷ 250ms) | +8% |
| 暴風雨 (STORM) | 弾の量 +50% / 弾の速度 +50% | +11% |
| 巨人 (GIANT) | 自機サイズ +100%(当たり判定・見た目とも 2 倍) | +7% |
| 加速 (RUSH) | 譜面の再生速度 +50%(曲と弾幕の発射が 1.5 倍で進む。曲の音程も上がる。弾速・予兆の長さは実時間のまま) | +6% |
| 暗闇 (DARK) | 自機の周囲しか弾が見えない(自機から 60px までは全部見え、150px に向けてなめらかに薄れて、それより遠い弾は見えない。**低速(Shift / 右クリック)の間は、この範囲が 0.55 倍**にさらに狭まる。出入りはなめらか)。**発射地点は見える**: 予兆のリング・スライダーの軌道は常に表示し、発射後も 0.9 秒だけ発射地点に印(リング)を残す。描画だけの MOD で、当たり判定・難易度(Lv)は変わらない | +5% |
| 練習 (PRACTICE) | ゲージが 0 になってもゲームオーバーにならず、最後まで続けられる(クリアできる)。以前の「練習モード」の設定は、この MOD に引き継がれる | **−50%(×0.5)** |

- **重ねがけはすべて乗算**です。ベーススコアは、暴風雨(×1.11)と巨人(×1.07)なら 1.11 × 1.07 = 1.1877、練習(×0.5)と暗闇(×1.05)なら 0.525。弾サイズ・弾数・弾速・自機サイズ・再生速度も、重ねると倍率がかかります(体力は短いほう、低体力の半減は 1 つでも無効なら無効)。
- **難易度(Lv)は MOD を適用した弾幕で測り直します。** メニューの難易度リストは、MOD にチェックを入れると MOD 適用後の Lv になり(`[MODなし x.x]` を添える)、プレイ中の表示・リザルトも適用後の Lv です。弾数の自動調整(譜面ごとの生成)は MOD の前に済ませるので、MOD で難しくなった分はそのまま Lv に出ます。
  - **ベーススコアの加算の決め方**: 手元の 46 譜面の平均で、MOD 1 つで上がる Lv は 暴風雨 +56%(+2.4)/ 巨人 +34%(+1.5)/ 加速 +30%(+1.3)/ 地獄 +16%(+0.7)/ 暗闇 0%。加算は、この上昇のおよそ 0.2 倍を基準にした緩やかなもので(暴風雨 +11% / 巨人 +7% / 加速 +6%)、Lv に出ない厳しさがある地獄(体力 250→150ms・低体力の半減なし)と暗闇(見えにくさ)は +5% ずつ上乗せしました(+8% / +5%)。MOD や譜面生成を変えたら測り直してください。
- 体力バーの長さは、ゲージ満タンぶんの被弾時間(250ms)に対する割合で決まります(地獄は 0.6 倍)。バーの中身(残量の割合)は変わらず、短いバーが「体力の少なさ」を表します。
- ベーススコアの倍率は、ベースの 1,000,000 にだけかかります。グレイズボーナス(最大 30,000)は変わらず、被ダメージ係数は全体にかかります。ランクは MOD の倍率を打ち消した達成率で決まります(上記)。
- 被ダメージ係数は「ゲージ満タン = 1」の単位で計算するので、体力が短い MOD では同じ被弾時間でも係数が大きく下がります(150ms の被弾で 1.0 → 係数 0.61)。

## 画面表示(HUD)
フィールド内に、シンプルな表示だけを置いています。

- **左上**: 体力バー。斜めに切ったケース入りのバーで、塗りは上が明るく下が暗い 2 段のグラデーション(左が暗く右が明るい)、上面の光沢、バーと平行な斜めの縞(流れる)、流れる光の帯、底からにじむ色、左に斜めの 3 本線の飾り。残量で青緑 → 琥珀 → 赤へ連続的に変色し(枠も赤みを帯びる)、被弾で減った分は白い残像がゆっくり縮みます。20% の位置の小さな三角は「ここから被ダメージ半減」。**先端は状態で動きが変わります**: 回復中は縞と光が速く流れ、先端が明るくなり火の粉が立ちのぼる / 通常はゆっくり流れる / 被弾中は先端から赤い火花が散る / 休憩地帯(回復が止まっている間)は縞と光が止まり、バーが冷たい色に沈み、先端に静かな波紋が広がる
- **体力が低いとき**: 35% 以下から、画面の左右端が赤くなります(0 に近づくほど濃く広く、残量の変化にゆっくり追従。点滅・脈動はなし)
- **右上**: スコア(大きく)と、その下に曲の進捗度(小数 2 桁の %)。休憩地帯中は BREAK と表示(弾が抜けたら中央にカウントダウン)。**被ダメージでスコアが減っている間は、数字(と SCORE の文字)が赤くなります**(減り終わるとなめらかに白へ戻る)
- **自機が体力バーやスコアに近づくと、それらが薄くなります**(自機の縁から 90px 以内で薄れ始め、重なると不透明度 14% まで。離れるとなめらかに戻る。`HUD_FADE_DIST` / `HUD_FADE_MIN`)
- 左の余白: 曲名・難易度名・Lv(MOD ありなら適用後の Lv と「MODなし」)・付けた MOD のタグ
- 右の余白: グレイズ数、ダメージ量
- 下端の進行バー: 休憩地帯は淡い区間で示します

## 弾の見た目
発射直後でまだ当たり判定のない弾(自機が発射点の近くにいたときの弾)は、**中抜きのリング**で表示します。塗りつぶしの弾になった瞬間から当たり判定があります。
**スライダーの軌道**は、太い半透明の帯と細い中心線です。折れ角のあるスライダーでも、関節が重なって濃くなったり、角にトゲが出たりしないよう、不透明な 1 本の線(角と端は丸い)をグループ化して、全体に 1 度だけ透明度をかけて描いています(`ArenaView.sync_sliders`)。

## キアイの光
譜面のタイミングポイントには、キアイ(kiai)の区間が含まれています(`bm.timing_points[*].kiai`、`Beatmap.kiai_at(t)`)。以前から弾の色(キアイ用パレット)には使っていましたが、キアイ中は**テンポに合わせて背景と弾幕が少し光ります**。
- **拍**: 直前の赤線(非継承のタイミングポイント)から数えた拍の位相(`Beatmap.beat_phase_at`)。拍の頭で約 40ms かけて立ち上がり、次の拍に向けてなめらかに消えていきます(BPM が変わる譜面でも、新しい拍で数えます)。曲(音)に合わせるため、オフセット設定は引いて数え、再生速度 MOD の分も換算します。
- **光る場所**: 背景の画像が**僅かに**明るくなる(最大 1.14 倍)/ フィールドの暗い下地がごく僅かに薄くなる(不透明度 −0.035) / **弾の周りに、弾の色の淡い光(加算合成のハロー)が広がる**。ピーク以外でも、キアイ中は下限 12% の光が残ります。弾の光は描画だけで、判定は変わりません(暗闇 MOD のときは、見える範囲の外の弾の光も出ません)。
- **出入り**: キアイの始まり・終わりは、約 0.25 秒かけてなめらかに出入りします。キアイのない譜面・区間では何も起きません。ゲームオーバー・クリアの間は消えます。
- 実時間の確認: `--smoke-kiai`(Reol Extra のキアイ 50〜70 秒で、光が 0.300 秒間隔=BPM 200 の拍ごとに山を作り、キアイの前は 0 になることを確認)。

## 自機の見た目
シンプルさを保った、鋭い矢じり型の機体です。
- 機体は 2 トーン(外側の翼が濃い青、中央に明るい背骨)で、白い縁取り。被弾中は赤みを帯びる。
- 淡い光が機体を包む。
- **動くと後ろに尾が伸びます**: 動いた軌跡が約 0.2 秒で細く薄れて消える 1 本の帯と、動きの速さに応じて伸び縮みする後ろの炎(止まっていると短い)。時間ベースなので、フレームレートによらず同じ長さです。
- 低速(Shift / 右クリック)の間は、周りを 4 本の短い弧が回ります。
- ゲージが減っているときは、残量のリング(色は残量で変わる)。中心の白と赤の点が当たり判定です。
- MOD「巨人」では、機体・光・尾・リングがすべて同じ倍率で大きくなります。
- **機体は弾の下の層に描きます**(予兆・軌道の上、弾の下)。自機が大きくても、機体の下にある弾が隠れず、弾が機体の上に見えます。当たり判定の点・低速時の弧・ゲージのリングだけは、位置の目安として弾の上に描きます。

## ゲームオーバー
ゲージが 0 になると、その場で爆散します(加算合成で光る): 中心の小さな光、3 重の衝撃波(円 / 回転する六角形 / 大きく薄い円)、放射状の光条(彗星のように伸びて縮む)、尾を引いて減速する火花、回転して散る自機の破片、余韻の火の粉。曲はテープストップのように減速して止まり、GAME OVER が表示されます(画面全体のフラッシュ・点滅・画面揺れはありません)。

## 効果音
音は、**専用の音作りツールで作って、音声ファイル(`assets/sfx/`)に書き出し、ゲームはそれを読んで鳴らします**(`scripts/sfx_bank.gd`)。以前は起動時に波形を合成していたので、軽い計算に抑える必要があり、音の質に限りがありました。ファイルにしたので、重い処理(帯域制限した発振・フィルター・残響・先読みリミッター)を使って作り込めます。起動時の合成の待ち(約 130 ms)も、なくなりました。音量はメニュー、またはポーズ中に調整できます。

### 弾幕の発射音・ダメージ音
osu! のヒットサウンドの役割(normal / whistle / finish / clap)を土台に、名前にこだわらず「連打されても気持ちよく、耳が疲れない」ことを優先して作りました。
音作りの方針: 正弦波を電子的に掃くのではなく、**叩かれた物体の音(モーダル合成: 木・ガラス・鉄琴・カリンバ)**を使い、自然な倍音と、ばちの硬さで決まる明るさを出す / 頭は 1〜2 ms で鋭く立ち上げ、何度も鳴る音ほど低い音を引きずらない(曲の低音とぶつからない)/ 響きは短く自然な部屋の残響(FDN)/ 音程のある音は E のペンタトニック・E メジャーの音。

| 音 | 使われる場面 | 音の作り |
|---|---|---|
| pop | 通常の弾 | 木の塊を叩いた「トッ」(ウッドブロックのモード)+ ごく短い胴の低音。約 100 ms で消える |
| whistle | ホイッスル付きのノート | ガラスのチャイム「ピン」(A6 前後)。基音のすぐそばのもう 1 つの振動がゆっくりうなって、きらめく |
| clap | クラップ付きのノート | 808 の手拍子: 帯域ノイズが 3 回はじけてから短い尾 + 小さな部屋の響き(約 270 ms) |
| boom | フィニッシュ付き・スライダー端 | サブ低音が落ち込む「ドン」+ 芯 + 硬い当たり + シンバルのきらめき。ステレオ |
| tick | スライダーの連射・スピナー | 音程を感じない小さな粒「チッ」: シェイカーのような帯域ノイズ + 倍音が整数比でない約 4 ms の当たり。曲のメロディと同じ時刻に続けて鳴りやすいので、音程を持たせない(どの調の曲でもメロディとぶつからない) |
| hit | 弾に触れた瞬間 | 重い打撃 + 金属的に落ちる FM + サンプルホールドで粗くしたノイズの「ザクッ」(弾の木・ガラスの音とはっきり違う) |
| hit_loop | 弾に触れている間 | ざらついたノイズと、12 Hz で脈打つ低い唸りの「ジジジ…」(ループ)。ダメージは触れている間ずっと続くので、音も続く |
| explosion | ゲームオーバー | 低い地鳴り + 暗くなるノイズ + 破裂 + 左右に散る破片 + 大きな響き(約 1.7 秒)。ステレオ |

**触れている間の音**: 弾に触れた瞬間に hit を 1 回鳴らし、触れている間は hit_loop をループ再生します(`Sfx.touch_damage` を毎フレーム呼ぶ。立ち上がり 30 ms・消えるまで 140 ms でなめらかに出入りし、体力が減るほど音程が最大 +22% 上がって切迫感が出る)。呼ばれなくなる(離れた・ポーズ・ゲームオーバー)と、自動で消えます。

発射音は、各音 6 種類(boom は 4 種類)の変種からランダムに選び(同じ変種は続けて鳴らさない)、さらに音程を少し揺らします(pop ±3% / clap ±4% / tick ±4% / boom ±2%。音程のはっきりした whistle は ±0.4% にとどめ、曲と音程がずれないようにする)。被弾音・爆発音は揺らしません。
**左右の定位**: 発射音は弾の発生源の横の位置に合わせて左右に振ります(`GameSim.sfx_pan`。7 段階のバス `SfxPan*` に `AudioEffectPanner` を付けて振り分け、振り幅は最大 ±0.5)。被弾の hit は自機の位置で振ります。
UI の音(ホバー・クリック・選択・決定・開閉・スタンプなど 15 種類)も同じ方法で、カリンバ・マリンバ・鉄琴に統一しました(`scripts/ui/ui_sfx.gd`)。決定は左から右へ広がるアルペジオ、画面切り替えの風切り音は幕と同じく左から右へ動きます。

### 音作りのツール(`tools/`。書き出した exe には含めません)
- `tools/dsp.gd` … 信号処理の部品: モーダル合成(帯域通過の共振のかたまり)とばち(接している時間で硬さが変わる力の山)・正弦波の音程スイープ・加法合成・FM・帯域制限した矩形波/のこぎり波(PolyBLEP)・ノイズ(白/ピンク)・包絡・RBJ フィルター(周波数が動くものも)・飽和・サンプルホールド・左右の定位(動くものも)・FDN 残響(初期反射つき)と Freeverb 型の残響・先読みリミッター・聴感に近い大きさ(150 Hz 以下を落として測る)のそろえ・FFT・スペクトログラム。
- `tools/sfx_recipes.gd` … 音ごとのレシピ(部品を重ねる関数)。音の名前 → [変種の数, 目標の大きさ(dBFS), ピークの上限]。楽器のモード(木・マリンバ・鉄琴・カリンバ・ガラス)は定数にまとめてあります。仕上げで、直流除去・頭と末尾をなめらかに閉じる・無音の末尾を切る・目標の大きさにそろえる(ピークはリミッターで押さえる)を行います。乱数の種は音の名前と変種の番号から決めるので、同じレシピからは**ビット単位で同じファイル**ができます。
- `tools/sfx_forge.gd` … 書き出し。`godot --headless --path . --script tools/sfx_forge.gd`(`-- pop hit` のように名前も指定できる)。`-- --verify` は、今の `assets/sfx` がレシピどおりか確かめます(レシピを直して書き出し忘れると失敗)。
  - **聴き比べ**: レシピを直す前に `-- --snapshot` で今の音を `sfx_preview/before/` に取っておき、直したら `-- --preview` で書き出すと、`sfx_preview/index.html` に「今」と「前」の音が並びます(ブラウザで開く)。変種を 1 つずつ鳴らすボタンと、ゲーム中のように変種をランダムに 8 回鳴らす「連打」ボタン、スペクトログラム(縦: 40 Hz〜16 kHz の対数軸、下に波形)つき。`sfx_preview/` は `.gitignore` 済みで、`.gdignore` で Godot のインポートからも外しています。
- ファイルは「標準の WAV で、拡張子だけ `.sfx`」(`assets/sfx/<音>_<番号>.sfx`、合計約 2.1 MB)。Godot のインポートを通さず `AudioStreamWAV.load_from_buffer` で読むので、書き出した exe でも `export_presets.cfg` の `include_filter` だけで読めます。
- 確認: `tests/test_sfx.gd` が、全ファイルについて、そろっている・ピークが範囲内・先頭と末尾がゼロ(プチッと鳴らない)・直流成分がない・大きさが目標にそろっている・変種が違う波形・立ち上がり(発射音は 3 ms 以内)・音の役割どうしの関係(明るさ: tick > whistle > pop、tick ははっきりした音程を持たない、被弾と爆発は低く重い、UI の音は高すぎない)・ファイルがレシピどおり、を確かめます(`-- wav` で、読み込んだ音を WAV に書き出して聴けます)。`--smoke-sfx` は、(書き出した exe の中でも)ファイルが読めて鳴ること・発射音を左右に振れることを確かめます。

## 設定(`user://settings.cfg` に自動保存)
全体音量、音楽・効果音の音量、UI の音(オン / オフ)、操作方式(標準はマウス)、マウス感度、オフセット(音と弾のズレの校正)、MOD(練習を含む)。

## マルチプレイ(対戦・協力。サーバーなしの P2P)
タイトルの「マルチプレイ」から。**部屋を立てる人(ホスト)へ、招待コードで直接つなぎます**(最大 4 人)。中継サーバーは使いません(管理するものがありません)。

### つなぎ方(`scripts/net/net.gd`、`invite_code.gd`)
- **通信**: Godot 標準の ENet(UDP)。ホストが待ち受け、参加者がホストへつなぐ星型。ポートは UDP 24680〜24935 のうち空いている最初のもの。
- **ポート開放**: ホストが部屋を作ると、**UPnP** でルーターのポートを自動で開け(別スレッド)、ルーターが知っているグローバル IP を得ます(部屋を閉じると、ポートも閉じます)。UPnP が使えないルーターでは、公開 IP だけを `api.ipify.org` に問い合わせてコードに入れます(ルーターで UDP ポートを手動で開けていれば、それで参加できます)。
- **招待コード**: グローバル IP(4 バイト)+ LAN の IP(4)+ ポート(1)+ CRC-8(1)= 80 ビットを、32 進(I・L・O・U を除く)の 16 文字にしたもの(例: `K7CF-8DP0-N00G-A034`)。1 文字の入力ミスは必ず検出し、小文字・区切りなし・`O`/`I`/`L` の読み替えも受け付けます。参加者は、同じ LAN(IP の上位が同じ)なら LAN の IP から、そうでなければグローバル IP から順に試します(各 3.5 秒)。**IP アドレス(`a.b.c.d` または `a.b.c.d:ポート`)を直接入力しても**つなげます(VPN の IP など)。
- **できないこと**: プロバイダが IPv4 のアドレスを共有している(CGNAT など)と、外から直接はつなげません(その場合は Tailscale / ZeroTier などの VPN を使い、ホストの VPN の IP を入力)。この開発環境のルーターでは、UPnP による自動開放でグローバル IP が得られることを確認済みです(`--smoke-upnp`)。
- **安全のための作り**: 受け取るデータは `bytes_to_var`(オブジェクトは復元しない)で読み、型を確かめてから使います。`hello` が来ない接続は 5 秒で切り、ゲーム中・満員・版が違う参加は断ります。ホストは参加者を外せます(ロビーの ×)。

### ロビー(`scripts/ui/multi_screen.gd`)
入口(名前 / 部屋を作る / 招待コードで入る)→ ロビー。ホストが**モード**(対戦 / 協力)と、**曲・MOD**(選曲画面を「決定」モードで開く)を決め、**参加者が「準備完了」ボタンを押し**(曲を持っている人だけ押せる。ホストは開始を押す人なので数えない)、全員が曲を持っていて全員の準備ができたとき、ホストの「ゲーム開始」が押せます(ひとり部屋はそのまま開始できる)。ロビーの参加者の行に「準備完了 / 準備中…」が出ます。**モード・曲・MOD が変わるたび、ロビーに戻るたびに、準備完了は全員外れます**(変わった内容を確かめ直してもらうため)。曲を持っていない参加者には、**「ダウンロードして取り込む」ボタン**(進み具合つき。`scripts/song_download.gd`)を出します。osu! の公式サイトはログインが要るので、ログイン不要のミラー(**osu.direct を最優先**で、だめなら Nerinyan → catboy.best の順に試す。osu.direct を先にするのは、たいていの曲が取れるため。ボタンを押したときだけ通信)から曲の ID で取り、zip として読めること・部屋の譜面と同じ中身の難易度を含むことを確かめてから、ユーザーデータの `songs` に取り込みます(確かめられなければ次のミラーへ)。補助として、osu! の公式ページを開く「ブラウザで開く」(`https://osu.ppy.sh/beatmapsets/<曲ID>#osu/<難易度ID>`)と「曲フォルダを開く」も出します(自分で入れた .osz も、自動で見つかります)。曲の確認は、**譜面の中身の識別子**(`OsuParser.play_key`。難易度の数値・タイミング・ノーツ・休憩だけから作り、題名・ID・タグ・ヒットサンプルなどは含めません)で行うので、配布元や版が違って、ファイルが少し違うだけの同じ譜面も「持っている」と判定されます(古い譜面は BeatmapSetID を持たないので、`曲ID 曲名.osz` の名前の先頭の数字を使います)。参加者の手元の曲は識別子から自動で探します(2 秒ごとに再探索。`SongLibrary.info` の索引でファイルは開き直さない)。**MOD はホストのものが全員に掛かり**(全員が同じ弾幕になる)、操作方式・音量・オフセットは各自の設定のままです。ゲームが終わると全員がロビーへ戻ります(ホストが次の曲を選べます)。
**配置**: 「戻る」は左上(入口は「◀ タイトル」、ロビーは「◀ 退出」)、「設定」は右上、「ゲーム開始」「準備完了」は右下です。他の参加者がいるホストが「退出」(Esc も)を押すと、部屋が閉じてしまうので、先に「部屋を閉じますか？」の確認が出ます(参加者や、ひとりだけの部屋は、すぐ出ます)。ホストがまだ曲を選んでいないときは、参加者の画面の右下に「ホストが曲を選ぶのを待っています」と出ます。参加者の「遅延 N ms」は、1 秒ごとに更新されます。

### 同期のしくみ(`scripts/net/mp_game.gd`)
- **弾は通信しません**。どの端末も、同じ譜面から同じ弾幕を作り(生成は乱数を使わない決定的な処理)、曲の時計で自分で弾を動かします。通信は、位置・低速・スコア(30 回/秒)、被弾の報告、出来事だけです。判定は各自の端末で、自分の自機だけ行います(自分の見えている弾で当たる)。
- **開始**: ホストが開始を押すと、全員が曲・弾幕を作って「準備完了」(作った弾幕の要約つき。ホストと違う人は外す)を返し、全員そろうとホストが**共通の時計**での開始時刻を配ります。参加者は ping を測り続けてホストの時計との差を求めるので、全員が同じ瞬間に READY を数え始めます(実測: 曲の時計のずれは数 ms)。
- **対戦**: 各自が自分ひとりの `GameSim` を回します(体力が 0 でもゲームオーバーにならず、最後まで続く。MOD「練習」のスコア半減はなし)。自機狙いの弾も各自の自機を狙うので、互いの弾・被弾は干渉しません。他の人の自機は、その人の色の淡いゴーストで表示し、左に名前とスコアの一覧(1 秒ごとに順位で並べ替え)。終わったら最終成績を送り、リザルトに順位表(スコアの高い順、全員が終えたら 1 位に WIN)が出ます。
- **協力**: 同じフィールドで一緒に避けます。**体力は全員で 1 本を共有し、人数に応じて増えます**(満タン = 1 人ぶんの被弾時間 × 人数。全員の被弾時間を足して減るので、1 人あたりの負担はひとりのときと同じ)。ゲージ・スコア・ゲームオーバー・クリア・休憩の一掃は**ホストが決めます**: 参加者は自分の被弾時間・グレイズ・被弾回数を 15 回/秒でまとめて報告し(`g_ct`)、ホストが共有の状態を 20 回/秒(`g_cs`)、出来事(一掃・クリア・ゲームオーバー)を即時(`g_ev`)で配ります。休憩の一掃とクリアは「全員の周りが落ち着いている」ことが条件です。グレイズのボーナスは全員の合計を人数で割ります。**自機狙いの弾**は、ホストが撃つ 0.25 秒前に、狙う相手(スロット順の持ち回り)とその位置を決めて配るので、全員が同じ向きの弾になります(自機に近い発射点の猶予だけは、各自の自機で決めます)。
- **実測**(`--smoke-mp`。同じプロセス内のホストと参加者を、ボットで 20 秒ほど走らせる): 曲の時計のずれ 2〜8 ms、ゲージ・被弾回数・グレイズが一致、**弾の位置が一致**(最も近い弾までの距離 0.1px 以下)、クリア時のスコアが全員で一致。片道 120ms + ゆらぎ 30ms の遅延を再現しても(`lag120`)、同じ結果になります。全員が動かないと、ゲームオーバーが全員に同時に届きます(`coop fail`)。
- **ゲーム中の Esc**: 他の人がいるので、ゲームは止まりません。メニュー(音量・退出)が重なるだけです(リトライ・スキップはなし)。途中で抜けても、残りの人は続けられます(ホストが抜けると、全員が入口へ戻ります)。

## 音量(マウスホイール)
どの画面でも、**マウスホイールで音量**を変えられます(1 目盛り = 5%)。回すと画面上部に「全体 / 音楽 / 効果音」のメーターが一定時間(約 1.7 秒)出て、**全体音量**が変わります。メーターを**クリックしてから**回すと、その音量(音楽 / 効果音)が変わります。表示が消えると選択は保持されず、次に回したときは、また全体音量です。値は消えたときに保存されます。**バーはマウスでも動かせます**: バーをクリックするとその位置の音量になり、押したまま左右へ動かして調整できます(マウスがメーターの上にある間・ドラッグ中は消えません)。
- 選曲の曲リストのようなスクロールできる一覧・スライダーの上では、ホイールは本来の動き(スクロール・値の変更)に使います。メーターが出ている間と、Ctrl を押しながらのときは、どこでも音量になります。
- 実装は `scripts/volume.gd`(値の一元管理。音楽は「Music」バスに集め、効果音は `sfx.gd` の音量に反映)と `scripts/ui/hud_overlay.gd`(メーター・通知)。設定の「音」にも「音楽」のスライダーがあります。

## 選曲の軽さ・スクロール・カーソル
- **曲を選んだときの一瞬の停止**を解消: 曲を選ぶと、曲名などはすぐ出て、重い処理(`.osz` を開く・難易度ごとの弾幕の生成と難易度の計算・背景画像のデコード・試聴の音声の読み込み)は `WorkerThreadPool` の別スレッドで行い、終わったら難易度カードを入れ替えます(続けて選び直したら、古い結果は捨てます。読み込み中の「決定」は無視)。別スレッドにしたあとも、結果を画面へ反映する瞬間に主スレッドで数十 ms かかっていたため、さらに次を直しました: 難易度カードは 3 枚ずつ数フレームに分けて作る / MP3 の試聴は、あらかじめ試聴位置から始まる音声に切り出しておく(途中から流すと、探す処理で数十 ms 止まる) / 大きい背景画像は別スレッドで縮める / 前の曲の弾幕・譜面(大量の辞書)の解放も別スレッドに回す(主スレッドで手放すだけで十数 ms かかっていた)。実測(`--smoke-new`)では、曲の切り替えの前後を通して、最長フレームは約 11 ms(修正前は約 47 ms。もともとは 1 曲あたり 100〜500 ms の停止)。選曲画面を開くときも、曲の一覧に出す情報(題名・作者・識別子)は `user://song_index.json` の索引から得るので、`.osz` を全部は開き直しません(`SongLibrary.info`。ファイルの場所・大きさ・更新時刻で照合)。
- **なめらかなスクロール**: 曲一覧・難易度一覧は、ホイールで目標の位置を動かし、そこへ少しずつ近づきます(`scripts/ui/smooth_scroll.gd`)。選択の切り替えで見える位置へ動くときも同じです。揺れ・点滅はありません。
- **独自のマウスカーソル**: OS のカーソルはウィンドウの中では隠し(`MOUSE_MODE_HIDDEN`)、小さな輪と点を描きます(`scripts/ui/cursor_overlay.gd`)。ボタンなど押せるものの上では輪がなめらかに大きくなり、押している間は小さくなります。プレイ中のマウス操作(`CAPTURED`)では描きません。
- **アプリを閉じたときの停止**: 部屋を作った直後(UPnP を探している間、数秒)に閉じる・部屋を出ると、探索のスレッドを待って止まっていたので、待たずに手放し(終わってから回収)、ポートを閉じる処理も別スレッドにしました。アプリを閉じるときは、最長 2.5 秒だけ待ちます(`tests/prof_close.gd`)。

## .osz を開く(取り込み)
アプリで `.osz` を開くと、自動で取り込まれます(`scripts/osz_import.gd`)。ユーザーデータ内の `songs` にコピーし(すでに曲の置き場にあるファイルはそのまま使い、同じ物は重複して取り込みません)、**選曲画面でその曲を選んだ状態**にします。
- アプリが起動していなければ、起動して選曲画面へ。動いているときは、動いているアプリへ渡します(`scripts/single_instance.gd`: 127.0.0.1 の UDP 24660。あとから起動したほうは、渡して終了します)。
- プレイ中・マルチプレイのロビーでは、画面は変えず、取り込みと通知だけ(ロビーでは、部屋の曲が見つかります)。選曲画面以外へのドロップも、同じ取り込みになります。
- Windows で `.osz` をダブルクリックして開くには、設定の「ゲーム」で「プログラムから開く」に追加し(`scripts/file_assoc.gd`。現在のユーザーのレジストリのみ)、Windows の「既定のアプリ」で選びます。**既定のアプリを、アプリから直接切り替えることはできません**(Windows は、ユーザーの選択を偽造できないようにレジストリのハッシュで守っていて、アプリが勝手に変えることを認めていません)。そのため、追加したあとに「既定のアプリの設定を開く」(`ms-settings:defaultapps`)で「.osz」を検索して DDA を選ぶか、`.osz` を右クリック →「プログラムから開く」→ DDA →「常に使う」で選びます。起動コマンドは `DDA.exe -- "ファイル"`(引数だけで渡されても受け付けます)。追加は書き出した版だけの機能です。
- **`.osz` を開いたとき**は、常にこのアプリで取り込み、選曲画面でその曲を選びます(以前あった「osu! で開くか選ぶ」機能は、osu! にゲーム内ダウンロードがあり、`.osz` を開いて取り込むことが少ないので廃止しました)。プレイ中は画面を変えず、取り込みだけして通知を出します。
- **songs フォルダを見張ります**: `songs` フォルダ(実行ファイルの隣・ユーザーデータ内など、曲の置き場)に `.osz` を置くと、約 2〜4 秒後に画面の下に「曲が追加されました: …」と出て、選曲画面なら一覧に加わります(コピーの途中で読まないよう、大きさが 2 回続けて同じになってから知らせます。プレイ中は見張りません。アプリで取り込んだ曲は、知らせません)。

## アプリ内アップデート
起動時に、GitHub のリリース(`mametaro2023/DDA`。ベータのプレリリースも対象)を確認し(`scripts/updater.gd`。設定の「起動時に更新を確認する」で切れます)、新しいバージョンがあると、タイトル画面に「新しいバージョン v… があります」が出ます。押すとリリースノートが出て、「今すぐ更新」で:
1. リリースの zip をダウンロード(進み具合を表示)し、サイズと SHA-256 を確かめる
2. 中の `DDA.exe`・`README.txt`・`LICENSE-Godot.txt` だけを取り出す(ほかのファイル・`songs` には触れない)
3. このアプリを終了 → 別プロセス(PowerShell)が `DDA.exe` を入れ替え(失敗したら元へ戻す)→ 新しいアプリを自動で起動
- 安全のため、ダウンロード先はこのリポジトリのリリースのアドレスに限り、https で取得し、取り出した exe が Windows の実行ファイルの形でなければ断ります。置き場所に書き込めない場合・開発中の実行では、リリースのページを開くボタンになります。
- **自動更新**(設定の「見つけたら自動で更新する」。既定は入): 起動時の確認で新しいバージョンが見つかり、まだタイトル画面にいて(ほかのパネルを開いていない)、書き出した版で置き場所に書き込めるなら、**更新のパネルが自動で開き、すぐダウンロード → 検証 → 入れ替え → 再起動**します(曲や設定には触れません)。ダウンロード中は「キャンセル」(Esc・✕も同じ)で中止して、そのまま遊べます。キャンセルすると、次の起動でまた自動で始まります。**同じ版で更新を繰り返さない**ための印(`last_auto_update`)を残し、自動更新を始めたのにまだ古いままなら(版の付け間違いなど)、次からは案内のボタンだけにします。切ってあるとき・入れ替えられない環境では、これまでどおり案内のボタンだけです。確認は `--smoke-autoupdate`。
- 確認には `tests/fake_release_server.js`(GitHub API のふりをする手元のサーバー)と `--smoke-update` を使います(確認 → ダウンロード → 検証 → 入れ替え → 再起動、ハッシュが合わない zip を断ること)。**アップデート機能が入ったのは v0.3.0 からなので、v0.2.0 以前は自動では更新できません(手動で入れ替えます)。

## 配布(ベータ版)
本体のみを配布します(**曲・譜面は同梱しません**。プレイヤーが `.osz` を追加します)。現在は **ベータ版 v0.6.0**(`project.godot` の `config/version = "0.6.0-beta"`。マルチプレイは、全員が同じ版であることが条件です)。
- **書き出し設定**: `export_presets.cfg`(Windows Desktop / x86_64)。実行ファイルにパックを埋め込んだ単一の `DDA.exe`。テスト・`.osz`・README・ビルド用ファイルは含めない(`exclude_filter`)。書き出し先は `build/DDA_beta/`。
- **ビルド**(`build.bat`。ASCII のみ・CRLF で書いてあり、cmd から実行できます。実際にビルド済みで、`DDA.exe` 約 109MB / zip 約 38MB。書き出した `.exe` を単体で起動し、`songs/` の曲でタイトル → プレイの流れが動くことも確認済み): `build.bat` が、書き出し → `README.txt` / `LICENSE-Godot.txt` / `songs/`(曲の置き場)の同梱 → `build/DDA_beta_v0.4.0.zip` の作成までを行います。
- **事前に必要なもの**: Godot 4.7.2 の**エクスポートテンプレート**(Godot エディタの「エクスポートテンプレートを管理」からインストール)。この開発環境では、Windows 用のみを `%APPDATA%/Godot/export_templates/4.7.2.stable/` に導入済みです。未導入だと `.exe` は作れません(パック `--export-pack` までは作れます)。
- **同梱物**(`dist_files/`): プレイヤー向け `README.txt`(遊び方の案内・曲の追加方法・設定の保存場所・ベータ版の注意)、Godot の MIT ライセンス表記、`songs/README.txt`。
- **曲の場所**: 配布版では、`DDA.exe` の隣の `songs/`(と、ユーザーデータ内の `songs/`)を探します。
- **アイコン**: `icon.svg`(ゲームのウィンドウ・タスクバー用)。`.exe` ファイル自体のアイコンは、rcedit を設定していないので既定のままです。

## 構成
- `scripts/osu/` … パーサ、スライダー軌道、osz 読み込み、星評価の推定(難易度の基準用)
- `scripts/mods.gd` … MOD の定義と効果の合成
- `scripts/game/` … 弾幕生成(`pattern_gen.gd`)、進行(`game_sim.gd`)、弾(`bullet_field.gd`)、効果音(`sfx.gd`。ファイルの読み込みは `scripts/sfx_bank.gd`)、画面
- `scripts/ui/` … UI の触り心地: 効果音(`ui_sfx.gd`)、全ボタンへの自動の弾み(`juice.gd`)、粒と輪(`ui_fx.gd`)、画面切り替えの幕(`screen_wipe.gd`)。タイトル画面(`title_screen.gd`)、遊び方パネル(`howto_panel.gd`)、選曲画面(`menu_screen.gd`)、設定パネル(`options_panel.gd`。トグルのカードは `toggle_card.gd`)、MOD パネル(`mod_panel.gd`)、リザルト(`result_screen.gd`、ランクのメーター `rank_meter.gd`、体力のグラフ `hp_graph.gd`)、共通スタイル(`ui_style.gd`)
- `scripts/song_library.gd` … 曲(.osz)の探索(タイトルと選曲が共通で使う)と、譜面の MD5 から曲を探す(マルチプレイ)
- `scripts/net/` … マルチプレイ: 通信層(`net.gd`)、招待コード(`invite_code.gd`)、プレイ中の同期(`mp_game.gd`)。画面は `scripts/ui/multi_screen.gd`

## 処理と描画の分離(判定は 1000 Hz)
- ゲームの進行・当たり判定・スコア(`game_sim.gd` / `bullet_field.gd`)は、描画・音声・ノードに依存しない純粋なロジックです(ヘッドレスのテストがそのまま回せます)。描画は `arena_view.gd` / `game_screen.gd` が sim の状態を読むだけです。
- 判定は描画のフレームレートに縛られません。`game_screen.gd` は 1 フレームごとに、曲クロックに追いつくまで sim を **`SIM_STEP` = 1 ms 刻み**で進めます(60 fps なら 1 フレームに約 17 回、144 fps なら約 7 回)。当たり判定・被弾時間・ゲージ・グレイズは ms 単位で計算され、発射時刻の誤差も 1 ms 以内です。入力は、キーボードなら各ステップで押している方向を、マウスならそのフレームの移動量を各ステップに等分して渡します。
- **曲クロックの滑らかさ**: 音声クロックはミキサーのかたまり単位でしか更新されないため、そのまま使うとフレームごとの増分がばらつき(止まって次に跳ぶ)、弾の移動距離がフレームごとに違ってカクついて見えます。そこで曲クロックは描画のフレーム時間で滑らかに進め、音声とのずれだけを `CLOCK_PULL` = 4/秒の割合でゆっくり寄せます(0.1 秒以上ずれたら直接合わせます)。実測(約 320 fps): 増分のばらつきは標準偏差 1.22 ms → 0.08 ms、最大 5 ms → 0.34 ms、停止フレームは 6% → 0。音声とのずれは平均 0 ms・最大 9 ms 程度(`--smoke-clock`)。
- 処理が重く 1 フレームに `SIM_MAX_STEPS`(100)回では追いつかない場合だけ、刻みを粗くして時刻を合わせます(通常は起きません)。
- 費用の実測(`tests/test_sim.gd ... 1khz`): 1 ステップ約 0.02〜0.04 ms(弾 100〜200 発)で、1000 Hz 進めても実時間の 2〜4% 程度です。
