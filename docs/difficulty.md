# 難易度

## 難易度(Danmaku 難易度 v4)
このゲーム独自の指標です。**画面内にある弾の数(密度)**を軸に、弾速・弾サイズを補助項として測り、**本家の星と同じ目盛り**の Lv で表します。

1. 各弾が画面から出るまでの時間を計算し、0.1 秒ごとの「画面内の弾数 N(t)」を求める。**計測は「最初のノーツ(最初に弾を撃つイベント)」から「最後の発射」まで**で、曲頭のイントロは含めません(イントロの長さで難易度は変わりません)。
2. `score = 0.5 * 平均(N) + 0.5 * 上位5%点(N)`
3. `adj = score * (弾速 / 150)^1.25 * (危険半径 / 9.9)^1`(危険半径 = 実際の弾の当たり判定半径 + 実際の自機の当たり判定半径(上の 1.25 倍・1.15 倍を含む)。9.9 は弾サイズ 6.75 のときの危険半径。速い/大きい弾、大きい自機ほど adj が大きい。弾速の指数は、弾速が 2 倍だと画面内の弾数が約半分になる分を相殺した上で「速いほど難しい」にするため 1 を超えて 1.25 にしてある)
4. **長さ(持久力)の補正**: `adj` に `length_factor = clamp((T / 120)^0.15, 0.8, 1.3)` を掛ける(T = 手順 1 と同じ「最初のノーツ〜最後の発射」の秒数から、**休憩地帯と重なる時間を引いたもの**。弾の来ない休憩は持久力に数えない。MOD「加速」では休憩も 1/1.5 になる)。基準の 2 分で 1 倍、5 分で約 1.15 倍、75 秒で約 0.93 倍。密度が同じなら長い譜面ほど難しくなる(平均・上位 5% 点は長さに依存しないので、長さの効果はここだけ)。定数は `LENGTH_REF` / `LENGTH_EXP` / `LENGTH_MIN` / `LENGTH_MAX`。
5. `Lv = 補正後の adj を TARGET_TABLE(★→弾数の表)で逆引きした★換算値 − LEVEL_SHIFT(1.0)`(例: adj 80 → 表では 3.7 なので Lv 2.7、adj 165 → 5.9 なので Lv 4.9)。**Lv の目盛りを 1 だけ厳しくしてあります**: 同じ弾幕の Lv は、以前より約 1 小さく出ます。生成の目標も、その分だけ上の★の弾数に合わせるので(`target_score_for(★ + 1)`)、同じ Lv の弾幕は、以前より弾が多く難しくなります(Lv ≒ 推定★ は変わりません)。`Lv` の色の段階(`ui_style.gd` の `LEVEL_STOPS`)は、そのままです。

### 本家の星に近づける仕組み
- 基準として、本家の星評価を `scripts/osu/star_rating.gd` で推定する(サンプル 14 譜面の公式値と平均誤差 0.14★。他の曲での精度は未検証)。難易度そのものの定義には使わない。
- 目標の Lv は推定★そのもの。`pattern_gen.gd` の `TARGET_TABLE` で目標の弾数を決め、adj がそれに合うまで弾数の倍率を自動調整する。弾数は、その瞬間の局所ノーツ密度に比例する(曲の盛り上がりに沿って増減)。
- **弾の生成が合わせるのは、長さの補正を除いた密度だけ**です。長い譜面の弾数を減らして Lv を合わせることはしません。そのため Lv は、長い譜面では推定★より高く、短い譜面では低くなります(サンプル: Reol の約 75 秒の譜面は −0.1〜−0.5、Soleily(208 秒)は +0.1〜+0.3、Sound Chimera(297 秒)は +0.5〜+0.9)。
- 弾速は★に応じて ±15%(約 130〜175 px/s)だけ変える。微調整であり、効き方(`SPEED_EXP`)は実測が難しいので控えめな値。人間のプレイで確かめるための実験がある(下記「弾速の実験」)。
- 弾数を自動調整しても、弾数の下限/上限のせいで目標に届かない分は、弾サイズ(基準の 0.6〜1.4 倍)で吸収する。
- **弾サイズの効き(`SIZE_EXP` = 1.3。v0.14 までは 1.0)**: ボットで弾数と弾サイズを少しずつ変え、被弾の増え方を比べて決めました(`tools/difficulty_study.gd -- elastic`。32 譜面・開始位置 3 通り・14 並列で約 6〜9 分)。危険半径を大きくしたときの効きは、弾数を同じ割合で増やしたときの 1.0〜1.8 倍(強いボット 1.1〜1.3、弱いボット 1.7〜1.8、人間に近いボット 1.0〜1.4)で、多くは 1.3 前後でした。自機の大きさ(巨人)は、弾の大きさより強く効きます(約 2)。弾速は、発射が同じなら、ボットの被弾はほぼ変わりません。人間に近いボットは、反応の遅れ・ぶれ・自分の大きさ・低速の使い分けを入れたもので、保存されたリプレイに合わせて強さを決めます(`-- calib`。23 プレイで、遅れ 0.05 秒のとき被弾の合計が人間とほぼ同じ。ただし、どの譜面が難しいかの順は、まだ合いません)。
  - 1.0 → 1.3 で、同じ弾幕の Lv は平均 −0.09(難しい譜面ほど小さい弾が多く、最大 −0.22)。作り直すと、そのぶん弾が平均 +2.5%(最大 +8%)増えます(`-- sizeexp`)。
  - **前の版のリプレイ**は、指数を記録していないので、前の指数(1.0。`PatternGen.SIZE_EXP_LEGACY`)で弾幕を作り直して再生します(`Replay.play_settings`。手元の 26 件すべてで弾幕の指紋が一致)。新しいリプレイは、設定に `size_exp` を記録します。
- 自機狙いや弾種の変化は★に応じて解禁する。
- 長さの補正を除いた Lv は、サンプル譜面で推定★と ±0.1 以内で一致し、公式★との差は推定器の誤差(平均 0.14★)程度。長さの補正を含む Lv と公式★の順位相関は 0.95(`tests/test_rating.gd`)。
- MOD「加速」は曲が短くなる(実時間で 1/1.5)ので、長さの補正が少し下がります(Celsius' Extra: MODなし 5.33、加速 6.58)。

### 弾速の実験(人間のプレイで SPEED_EXP を確かめる)
Lv の計算は「弾が速いほど難しい」として弾速を `SPEED_EXP`(1.25)乗で効かせていますが、実測した値ではありません(ボットでは、同じ発射なら速い弾のほうが被弾が少なく、計算と逆でした。ただしボットは反応が速いので、人間とは違う可能性があります)。そこで、計算は今のまま、人間のプレイでデータを集めます(`scripts/speed_study.gd`)。
- 設定「その他」の **弾速の実験に参加する** を入れると、ひとりで遊ぶとき(弾幕に効く MOD なし。練習は可)、1 回ごとに次の条件のどれかで弾幕を作ります。プレイ中は条件を出しません。
  - **slow** 弾速 ×0.8 / **base** ふだんどおり / **fast** 弾速 ×1.25 … どれも**同じ Lv** に合わせる(弾数が自動で増減する)ので、計算が正しければ同じくらい難しいはず
  - **dense** 弾速はそのまま、目標の難易度 ×1.25(Lv が 1 段上)… 「難易度が 25% 上がると被弾がどれだけ増えるか」の物差し。fast と slow の差を `SPEED_EXP` の値に直すのに使う
- 条件は、譜面ごとに、遊んだ回数のいちばん少ないものを選びます(慣れの影響が条件に偏らないように)。選曲画面の Lv は変わりません(dense だけは結果画面の Lv が上がります)。
- 1 プレイごとに `user://speed_study.csv` に 1 行書きます(譜面・条件・弾速・Lv・被弾回数・ダメージ量・遊んだ時間・ゲームオーバーか など。外には送りません)。
- 集計: `godot --headless --path . --script tools/speed_study_report.gd`。条件ごとの「被弾 /分」と、fast / slow・dense / base の比、`SPEED_EXP` の推定を出します(4 条件をすべて遊んだ譜面が 5 つ以上、被弾の合計が 3 秒以上になるまでは推定を出しません)。fast / slow が 1 より大きければ、速い弾は計算より難しい(`SPEED_EXP` を上げる)、小さければ易しい(下げる)。

難易度(Lv・本家★の推定・MODなしの Lv)は小数点以下 2 位まで表示します。メニューの難易度リストは Lv の低い順に並び、括弧内に本家★の推定、平均/最大の弾数、弾速、弾径を表示します。
