# アップデートと配布

## アプリ内アップデート
起動時に、GitHub のリリース(`mametaro2023/DDA`。ベータのプレリリースも対象)を確認し(`scripts/updater.gd`。設定の「更新を確認する」で切れます)、新しいバージョンがあると、タイトル画面に「新しいバージョン v… があります」が出ます。押すとリリースノートが出て、「今すぐ更新」で:
1. リリースの zip をダウンロード(進み具合を表示)し、サイズと SHA-256 を確かめる
2. 中の `Danmaku.exe`(名前を変える前のリリースは `DDA.exe`)・`README.txt`・`LICENSE-Godot.txt` だけを取り出す(ほかのファイル・`songs` には触れない)
3. このアプリを終了 → 別プロセス(PowerShell)が、いま動いている exe を入れ替え(ファイル名はそのまま)(失敗したら元へ戻す)→ 新しいアプリを自動で起動
- 安全のため、ダウンロード先はこのリポジトリのリリースのアドレスに限り、https で取得し、取り出した exe が Windows の実行ファイルの形でなければ断ります。置き場所に書き込めない場合・開発中の実行では、リリースのページを開くボタンになります。
- **自動更新**(設定の「見つけたら自動で更新する」。既定は入): 起動時の確認で新しいバージョンが見つかり、まだタイトル画面にいて(ほかのパネルを開いていない)、書き出した版で置き場所に書き込めるなら、**更新のパネルが自動で開き、すぐダウンロード → 検証 → 入れ替え → 再起動**します(曲や設定には触れません)。ダウンロード中は「キャンセル」(Esc・✕も同じ)で中止して、そのまま遊べます。キャンセルすると、次の起動でまた自動で始まります。**同じ版で更新を繰り返さない**ための印(`last_auto_update`)を残し、自動更新を始めたのにまだ古いままなら(版の付け間違いなど)、次からは案内のボタンだけにします。切ってあるとき・入れ替えられない環境では、これまでどおり案内のボタンだけです。確認は `--smoke-autoupdate`。
- **起動したままの間に公開された新しいバージョンも知らせます**(設定の「更新を確認する」が入のとき。`Main._recheck_update`): 起動している間、30 分ごと(`UPDATE_RECHECK_SEC`。GitHub の API は 1 時間に 60 回まで)に、起動時と同じ確認をやり直し、まだ知らせていない新しい版が見つかったら、画面の下に「新しいバージョン v… が公開されました(タイトル画面から更新できます)」と 7 秒出します(タイトル画面なら、案内のボタンも出ます)。**知らせるだけで、自動更新はしません**(起動時の自動更新の判断は、起動時の確認のときだけ。更新は、タイトル画面の案内のボタンから、使う人が始めます)。同じ版は 1 度だけ知らせます。**プレイ中に見つかったときは、画面の邪魔をしないよう知らせずに取っておき、プレイを離れて(リザルトなど)1.5 秒たってから知らせます**。確認中・ダウンロード中・入れ替えの準備ができているときは、再確認しません。あとの確認が通信の不調で失敗しても、見つけた新しい版の情報は消えません(`Updater.info`)。確認は `--smoke-updatenotice [api=http://127.0.0.1:8765/releases]`(`api=` をつけると、手元のサーバーに問い合わせて、定期の再確認 → 知らせるまで通して確かめる)。
- 確認には `tests/fake_release_server.js`(GitHub API のふりをする手元のサーバー)と `--smoke-update` を使います(確認 → ダウンロード → 検証 → 入れ替え → 再起動、ハッシュが合わない zip を断ること)。**アップデート機能が入ったのは v0.3.0 からなので、v0.2.0 以前は自動では更新できません(手動で入れ替えます)。

## 配布(ベータ版)
本体のみを配布します(**曲・譜面は同梱しません**。プレイヤーが `.osz` を追加します)。現在は **ベータ版 v0.16.0**(`project.godot` の `config/version = "0.16.0-beta"`。マルチプレイは、全員が同じ版であることが条件です)。
- **書き出し設定**: `export_presets.cfg`(Windows Desktop / x86_64)。実行ファイルにパックを埋め込んだ単一の `Danmaku.exe`。テスト・`.osz`・README・ビルド用ファイルは含めない(`exclude_filter`)。書き出し先は `build/Danmaku_beta/`。
- **ビルド**(`build.bat`。ASCII のみ・CRLF で書いてあり、cmd から実行できます。実際にビルド済みで、`Danmaku.exe` 約 109MB / zip 約 38MB。書き出した `.exe` を単体で起動し、`songs/` の曲でタイトル → プレイの流れが動くことも確認済み): `build.bat` が、書き出し → `README.txt` / `LICENSE-Godot.txt` / `songs/`(曲の置き場)の同梱 → `build/Danmaku_beta_v<版>.zip` の作成までを行います。
- **事前に必要なもの**: Godot 4.7.2 の**エクスポートテンプレート**(Godot エディタの「エクスポートテンプレートを管理」からインストール)。この開発環境では、Windows 用のみを `%APPDATA%/Godot/export_templates/4.7.2.stable/` に導入済みです。未導入だと `.exe` は作れません(パック `--export-pack` までは作れます)。
- **同梱物**(`dist_files/`): プレイヤー向け `README.txt`(遊び方の案内・曲の追加方法・設定の保存場所・ベータ版の注意)、Godot の MIT ライセンス表記、`songs/README.txt`。
- **曲の場所**: 配布版では、exe の隣の `songs/`(と、ユーザーデータ内の `songs/`)を探します。
- **アプリの名前**: 「DDA - osu! Danmaku Dodger」→ v0.8.0 で「DDA - Danmaku Dodger」(他社の商標を作品名に入れないため)→「Danmaku」と変えました(副題はなくしました)。ユーザーデータの場所はアプリの名前で決まるので、起動時に、前の名前の場所(`%APPDATA%\Godot\app_userdata\DDA - Danmaku Dodger` と `…\DDA - osu! Danmaku Dodger`)の中身を、今の場所(`…\Danmaku`)へ移します(`scripts/user_dir_migrate.gd`。今の場所にすでにあるもの(ログ・新しい版の設定など)は上書きしない)。
  - 実行ファイルは `Danmaku.exe`。アプリ内アップデートは、いま動いている exe を名前を変えずに入れ替えるので、前の版から更新した人の exe は `DDA.exe` のまま動きます。新しい版の更新機能は、zip の中の `Danmaku.exe`・`DDA.exe` のどちらも受け取ります。**ただし、名前を変える前の版(v0.10.1 まで)の更新機能は、zip の中に `DDA.exe` がないと更新を断ります**(そのときは「ダウンロードページを開く」に切り替わる)。配布の zip には `Danmaku.exe` だけを入れる(互換用の `DDA.exe` は入れない)と決めたので、v0.10.1 以前の利用者は、改名後の版(v0.11.0)へ 1 回だけ手動で入れ替えます(設定・曲・記録は、初めて起動したときに自動で引き継がれます)。
  - 引っ越しは、書き出した版だけで行います。ソースから動かしたとき(開発・確認)は移しません(前の名前の場所は、インストール済みの前の版やほかのブランチと共有しているため。`-- --migrate-user-dir` で移せます)。ソースから動かしたときは、前の名前の場所の `songs` も、読むだけで探します。
  - 「プログラムから開く」の登録は `Danmaku.osz` という名前になりました。前の版で `DDA.osz` として登録していた場合は、書き出した版の起動時に、新しい名前へ移します(`FileAssoc.migrate_legacy`)。
- **Windows の SmartScreen**: 実行ファイルに署名をしていないので、初めて起動するとき「Windows によって PC が保護されました」と出ることがあります。プレイヤー向けの `README.txt` に、「詳細情報」→「実行」で起動できることを書いてあります。
- **アイコン**: `icon.svg`(ゲームのウィンドウ・タスクバー用)。`.exe` ファイル自体のアイコンは、rcedit を設定していないので既定のままです。
