# リプレイ

## リプレイ(`scripts/replay.gd`、`replay_state.gd`、`game/replay_bar.gd`、`ui/replay_list.gd`)
ひとりで遊んだプレイ(クリア・ゲームオーバーとも)は、終わりに自動で保存されます。見返す入口は 3 つ: タイトルの「リプレイ」(保存してある一覧)/ リザルトの「リプレイ」(P キー)/ 選曲(lazer 風)の記録の再生ボタン。設定「その他」の「リプレイを自動で保存する」で切れます。マルチプレイ・開発用の自動操作(`--smoke` など)は保存しません。
- **入力だけを記録して、再シミュレーションする**: `GameSim` は決定的(弾幕は譜面から決まり、ボスの乱数もシード固定)なので、プレイ画面の `_step_sim` の 1 フレームごとに { 始めの時刻・進めた幅・ステップ数・入力(移動方向 / マウスの移動量)・低速・操作方式 } を記録し、再生は同じ値で `sim.step` / `step_relative` を呼ぶ(ステップの幅 = 幅 ÷ 回数、時刻の足し方まで同じなので、弾・ゲージ・スコアが完全に一致する)。弾幕は `Replay.build_game`(プレイ画面と同じ組み立て)で作り直す。曲・版・MOD が違えば弾幕の指紋(`events.size() * 100003 + bullets_total`)が合わず、「このバージョンでは再生できません」と(記録した版・いまの版つきで)出して開かない。指紋が合っても、版が変わって判定などが変わると結果がずれることがあるので、最後まで流したとき(飛んだときも)に、スコア・被弾・かすりが記録と合っているかを確かめ、ずれていれば注意を出す(`Replay.verify`)。
- **フレームの途中で止まれる再生**: 1 フレームの n 個のステップは、途中で止めて、あとで続きから進めても結果が変わらない(同じ順・同じ幅・同じ時刻の足し方)。0.25 倍などの遅い再生も、記録の 1 フレームを分けて進めるので、なめらかに動く(`Replay.Player.advance_to`)。
- **好きな秒へ飛ぶ(シーク)**: シムは巻き戻せないので、記録中に 5 秒ごとに状態(キーフレーム)を写しておき(`replay_state.gd`。スクリプトの変数を `get_property_list` で全部走査して複製するので、変数が増えても自動で含まれる。弾幕の予定表は複製せず、撃破 MOD の周回で伸びる分は大きさだけ覚えて足し引きする)、飛ぶときは「直前のキーフレームへ戻す → 目標の時刻まで再計算」(長くても 1 秒ほど)。イントロをスキップした区間は記録がないので、再生時計がその先まで飛ぶ。体力グラフのドラッグ中も、飛ぶのにかかった時間に合わせた間隔で、その秒へ飛び続ける(再生は止まり、離したら続く)。
  - **まだ見ていない秒へ飛ぶときの待ちをなくす**: 記録のキーフレームは 5 秒おきなので、そこから最大 5 秒ぶんを再計算すると、重い曲では 1 秒近く止まっていた。再生を開くと、裏のスレッド(`replay_dense.gd`)が別のシムを最初から流して、0.5 秒おきの状態を作る(40 秒で 1〜4 秒ほど。見ながら通ったところも足す)。飛ぶときは、記録と合わせて、いちばん近い状態から再計算するので、最大でも 0.5 秒ぶん(多くは数 ms〜数十 ms)。裏で使うので、`get_property_list` は主スレッドで先に済ませる(`State.warm`。裏のスレッドから呼ぶと落ちる)。あわせて、弾 1 発ごとの配列は、弾の数だけを写す(1 つの状態が 250 KB → 10〜15 KB。リプレイのファイルも小さくなる)。
  - **飛ぶ計算は、画面を止めずに分けて進める**: 飛ぶときは、直前のキーフレームへ戻したあと、目標までの再計算を、1 フレームに 10 ms までずつ進める(`replay_seek_budget_ms`)。近いときは、その場で終わる。70 ms を超えたら、画面の中ほどに「読み込み中…  45%」と進み具合を出す。そのあいだに新しく飛ぶ頼みが来たら、そちらに切り替える(ドラッグでも詰まらない)。
- **再生画面**: プレイ画面(`GameScreen`。lazer 風も同じ)に再生モードを足したもの。操作パネルは画面の下に固定で、プレイ画面はそのぶん縮めて見せる(自機が隠れない。H で隠すと元の大きさに戻り、画面の下の端へマウスを寄せると重ねて出る)。左のパネルに REPLAY の表示・日時・結果・再生中/停止中、画面の中ほどに操作の反応(「2.0x」「+5秒」など)を出す。曲はどの速さでも鳴る(速さに合わせて音程も変わる。速さを変えても途切れない)。曲の長さを過ぎたところでは鳴らさない(鳴らし直すと、曲の頭から鳴ってしまうため)。画面のクリックで再生/停止、別のウィンドウへ移ると止まる。
- パネル: 体力のグラフ(クリック・ドラッグでその秒へ。マウスを乗せると、その時刻の体力)と、下の段。左に「再生 / 停止」・±5 秒・「ジャンプ」(押すと上にメニューが開く: 最初へ・前の / 次の被弾・最後へ)・時刻、右に速さのスライダー(0.25〜8 倍の好きな値。対数の目盛りで、0.25・0.5・1・2・4・8 倍の近くでは吸い付く。数字を押すと 1 倍へ)・軌道の 表示 / 非表示・動画出力・操作の一覧(?)・閉じる。
  - **前の・次の被弾**(「ジャンプ」/ PgUp / PgDn): 被弾の 1.5 秒前へ飛ぶ(避けそこねた前後を見る)。
  - キー: Space 再生/停止 / ← → ±5 秒(Shift で 1 秒、Ctrl で 15 秒)/ , . 1 コマ / [ ] 速さ(区切りのよい速さへ)/ T 軌道の 表示 / 非表示 / Home End / PgUp PgDn 被弾 / H パネル / ? 一覧 / Esc 閉じる(一覧が開いていれば、まず一覧)。
- **自機の軌道**: 記録した全フレームの自機の位置から、過去 3 秒の尾を描く(出す / 出さない だけ)。自機の尾と同じ作りの 1 本の帯で、古いほど細く薄い。点は 3 px ごとに間引いてから角を丸める(Chaikin。1 フレームごとの細かい折れが、ギザギザに見えないように)。被弾した位置には赤い × を出す。動画にも映る。飛んだときは、自機の短い尾(残像)の古い点を捨てる(残すと、飛ぶ前の位置から太い帯が伸びる)。
- **リプレイの一覧**(タイトルの「リプレイ」。classic も lazer 風も同じパネル): 1 行 = 1 プレイ。左からランク / 曲名・作者と難易度・Lv と MOD(3 段。長いものは「…」で切り、行の幅は広げない)/ スコア・被弾・日時と長さ / 大きな「再生」と、その下の小さな「保存」「削除」。「再生」(Enter・ダブルクリック)/「保存」(S。自動の整理で消えず、件数にも入れない)/「削除」(Delete。2 度押し)。「すべて / クリア / ゲームオーバー / 保存済み」で絞り込み。見終わると、一覧へ戻る。一覧の要約は `index.json` に控える(ファイルを開かずに出すため。消えても作り直せる)。
- **動画出力**: 別のプロセスの Godot が、Movie Maker(`--write-movie`)で、リプレイを固定のフレーム時間で再生しながら画面と音を AVI(MJPEG + PCM)に書く(`main.gd` の `--replay-export`)。大きさと fps は「動画出力」で選ぶ(1280×720 60fps / 1920×1080 60fps / 1280×720 30fps)。最後は、プレイのときと同じく HUD がフェードして(ゲームオーバーは演出のあと)、リザルト画面(ボタンなし。数え上げ・ランクの判子などの効果音も入る)を 7 秒撮って終わる(クリアは、曲もそのまま鳴り続ける)。画面には操作パネルも REPLAY の表示も入らない。書き出し先は `ビデオ/Danmaku/`(終わると「出力先を開く」が出る)。進み具合は `user://replay_export_progress.txt` 経由で操作パネルに出る。ffmpeg(PATH にあるもの、またはアプリと同じフォルダの `ffmpeg.exe`)があれば、そのあと mp4(H.264 + AAC)に変換し、AVI は消す。書き出し中にもう一度押すと中止。
- 保存先は `user://replays/`(1 プレイ 1 ファイル。zstd で圧縮した `.rpl`。3 分の曲で 1 MB ほど)。保存済みを除いて新しい順に 30 件まで残し、記録(`records.gd`)に載っているプレイのリプレイは残す(記録から外れたら、ファイルも消す)。書き込みは裏のスレッドで行う(結果画面へ移るところで止まらないように)。
- 確認は `tests/test_replay.gd`(通しの再生・フレームの途中で止めながらの再生・シーク・周回をまたぐシーク・ファイルの往復・一覧・保存・整理・結果の確認)、`--smoke-replay [--export]`(実際にプレイ → 保存 → 再生 → 操作 → 被弾・一覧 → 動画出力(リザルトつき))。
