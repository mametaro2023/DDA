# 曲の読み込みと取り込み

## 曲の置き場所
曲(`.osz`)は、プロジェクト直下 / `songs/` / 実行ファイルの隣(と、その `songs/`)/ ユーザーデータ内の `songs/` に置くと一覧に出ます(**開発時、git のワークツリーで動かしたときは、元のリポジトリの直下と `songs/` も読む**。`.osz` は git に入れないので、新しいワークツリーでも曲が空にならない)。**同じ曲は 1 つにまとめます**(パスの書き方の違い・大文字小文字の違い・別の置き場にある同じ名前と大きさのコピー・名前が違っても譜面の中身が同じもの)。読めなかった .osz は、選曲画面の下に名前を出します。**ウィンドウに `.osz` をドラッグ&ドロップ**するか、選曲画面の「.osz を開く…」でも追加できます(osu!standard のみ対応)。ドロップは**どの画面でも**使え、**複数のファイルを一度に**入れられます。取り込んだ曲はユーザーデータの `songs` にコピーされる(次の起動でも残る)ので、元のファイルを消しても大丈夫です。選曲画面では、画面を作り直さずに一覧へ加わり、最後の曲が選ばれます。プレイ中とロビーでは、取り込みと通知だけです。ドロップを受け取った瞬間に、画面の真ん中から水色の輪が広がります(Godot には「ファイルをドラッグして窓に入った」ことを知る仕組みがなく、アプリが知るのはドロップされた瞬間だけです)。**曲を選んだときの弾幕は、一度作ったら直近 10 曲ぶんを覚えておく**ので(MOD 適用前のものを持つので、MOD を変えても使えます。弾幕 v2 だけは作り方が違うので、v1 と v2 を別々に覚えます。ファイルが差し替わると作り直します)、同じ曲に戻るときは速く読めます。難易度ごとの生成は並列に行います。

## osu! の Songs フォルダ(osu!stable に入っている曲を、そのまま使う)
設定の「曲」で **osu! の Songs フォルダの曲を使う** を入れると、osu!(osu!stable)に入っている曲を、**コピーせずに**選曲画面へ加えます(osu! は、.osz を展開して `Songs\<曲ID 曲名>\` に並べています。`SongLibrary.osu_song_dirs`)。
- **場所**: 空なら自動で探します(`%LOCALAPPDATA%\osu!` の `osu!.<ユーザー名>.cfg` の `BeatmapDirectory`、なければ `Songs`)。「フォルダを選ぶ…」で指定もできます(「自動で探す」で戻る)。
- **曲のパスは、その曲のフォルダ**です(`OszLoader` が .osz と同じように開く。音声・背景は、フォルダの中のファイル)。ほかの置き場の .osz と**中身が同じ譜面は 1 つにまとめます**(譜面の識別子。`OsuParser.play_key`)。マルチプレイの「曲を持っているか」の確認にも使われます。
- **osu!standard 以外の曲**(mania・taiko・catch だけの曲)は、読めなくて当然なので、選曲画面の「読み込めなかった曲」には出さず、黙って飛ばします。
- **何千曲あっても画面は止まりません**。重い処理(Songs の中のフォルダの一覧・曲ごとの索引づくり)は、すべて**裏のスレッド**で行います(`SongLibrary.start_osu_warmup`。設定を入れたときと、起動時・選曲画面を開いたときに始まる。見終えた曲は飛ばすので、増えた曲だけ調べ直す)。主スレッドは、できたぶんを読むだけです(`osu_song_dirs` / `take_ready` / `find_by_md5`。ファイルには触らない)。
- **選曲画面には、できた曲から順に足します**(`MenuScreen._pump_osu`。1 フレームに 4ms まで。曲の重複は辞書で確かめるので、曲が増えても遅くならない)。足している間は、画面の下に「osu! の曲を準備しています… 120 / 835」と出ます。前回選んでいた曲は、出てきたときに(まだ別の曲を選んでいなければ)選びます。設定の「曲」にも、同じ進み具合が出ます。
- **索引は保存します**(`user://song_index.json`。書き出しは索引をロックの外で行う)。2 回目からは、ほぼ一瞬で全曲が出ます。実測(835 フォルダ・629 曲): 索引なしでも、選曲画面を開いてから最長フレームは約 22ms、全曲が出そろうまで約 7.5 秒。索引ができたあとの `find_by_md5` + `find_all` は約 9ms。
- 確認は `tests/test_osu_folder.gd`(展開したフォルダが .osz と同じ譜面・音声・画像・索引になること、一覧・マルチプレイの探索に出ること、この PC に osu! があれば実際の Songs で)。

## 曲がないときの入口(`scripts/song_sources.gd`)
- **osu! の曲を使う**: 曲が 1 つもない選曲画面(classic・lazer 風とも)で、osu! の Songs フォルダが見つかれば(前に選んだ場所、なければ標準の場所)「osu! の曲を使う」を出します。押すと設定の「曲」の「osu! の Songs フォルダの曲を使う」を入れたのと同じになり(保存も)、裏で準備しながら一覧に足します。
- **URL から取り込む**: osu! の譜面ページの URL(`osu.ppy.sh/beatmapsets/<ID>`、古い `/s/<ID>` も)をコピーして、タイトル・選曲画面で **Ctrl+V**(入力欄に入力しているときを除く)、曲がないときの「URL から取り込む」、lazer 風の選曲画面の**検索欄に貼る**、のどれでも、その曲を取り込みます。ダウンロードはマルチプレイと同じ非公式ミラー(`song_download.gd`)で、初めては同意を求めます(設定 `mirror_consent` を共有)。進み具合は画面の下の通知に出し、終わったら `.osz` を開いたときと同じく選曲画面でその曲を選びます(タイトルからは選曲画面へ。すでにある曲は取り込み直さずに選ぶ)。難易度だけのページ(`/beatmaps/<ID>`)は、曲全体の ID が分からないので断ります。ダウンロードは main の子なので、画面を移っても続きます。
- **探す**(lazer 風の選曲画面の上のタブ「ソロ / 探す」。`ui/lazer/lazer_finder.gd`・`scripts/beatmap_search.gd`): osu! の曲を osu.direct の検索 API(非公式・ログイン不要。osu! 公式の API はアプリごとの秘密の鍵が要るので使わない)で探し、そのままダウンロードします。上に検索欄(入力が止まって 0.45 秒で探す・Enter ですぐ)・並び順(人気 / 新着 / お気に入り / ランダム。ランダムは、押すたびに人気順のランダムな位置から取って、並びもばらばらにする)・絞り込み(ランク済み / Loved / すべて)、下に曲のカードを 2 列で並べ(ジャケット・曲名・アーティストと譜面作者・osu!standard の難易度の★の色の点・★の幅・長さ・プレイ回数)、下までスクロールすると続きを読みます。検索欄が空なら並び順どおりの一覧で、初めはランク済みの人気順(おすすめ)です。カードのボタンは 取得 → 待機中 / 進み具合 → **遊ぶ**(押すと「ソロ」へ戻ってその曲を選ぶ)/ 再試行。アーティストと曲名が同じ曲がもう一覧にあれば、はじめから「遊ぶ」です。ダウンロードは順番待ちにでき(main の `fetch_song_set`。状態は `fetch_states` を選曲画面と共有)、「探す」から取った曲は選び直さずに一覧へ足すだけです。ジャケットは `user://web_covers` に保存して使い回します(画像は assets.ppy.sh からだけ取る)。Esc は、入力中なら入力を終え、そうでなければ「ソロ」へ戻ります。マルチプレイの曲選びのときは、タブを出しません。osu.direct が止まっているときは「つながりませんでした(osu.direct)」と「もう一度」を出します。見た目の確認は `--ui lazer --shot menu out.png finder`(`finder dl` で 2 つめの曲を実際に取る)。
- 確認は `tests/test_song_sources.gd`(URL の読み取り・勧める場所)と `--smoke-fetch`(`--ui lazer` / `--ui classic`。node で `tests/fake_mirror_server.js` を立てて、ボタン・同意・Ctrl+V・検索欄を通す)。

## .osz を開く(取り込み)
アプリで `.osz` を開くと、自動で取り込まれます(`scripts/osz_import.gd`)。ユーザーデータ内の `songs` にコピーし(すでに曲の置き場にあるファイルはそのまま使い、同じ物は重複して取り込みません)、**選曲画面でその曲を選んだ状態**にします。
- アプリが起動していなければ、起動して選曲画面へ。動いているときは、動いているアプリへ渡します(`scripts/single_instance.gd`: 127.0.0.1 の UDP 24660。あとから起動したほうは、渡して終了します)。
- プレイ中・マルチプレイのロビーでは、画面は変えず、取り込みと通知だけ(ロビーでは、部屋の曲が見つかります)。選曲画面以外へのドロップも、同じ取り込みになります。
- Windows で `.osz` をダブルクリックして開くには、設定の「ゲーム」で「プログラムから開く」に追加し(`scripts/file_assoc.gd`。現在のユーザーのレジストリのみ)、Windows の「既定のアプリ」で選びます。**既定のアプリを、アプリから直接切り替えることはできません**(Windows は、ユーザーの選択を偽造できないようにレジストリのハッシュで守っていて、アプリが勝手に変えることを認めていません)。そのため、追加したあとに「既定のアプリの設定を開く」(`ms-settings:defaultapps`)で「.osz」を検索して Danmaku を選ぶか、`.osz` を右クリック →「プログラムから開く」→ Danmaku →「常に使う」で選びます。起動コマンドは `Danmaku.exe -- "ファイル"`(引数だけで渡されても受け付けます)。追加は書き出した版だけの機能です。
- **`.osz` を開いたとき**は、常にこのアプリで取り込み、選曲画面でその曲を選びます(以前あった「osu! で開くか選ぶ」機能は、osu! にゲーム内ダウンロードがあり、`.osz` を開いて取り込むことが少ないので廃止しました)。プレイ中は画面を変えず、取り込みだけして通知を出します。
- **songs フォルダを見張ります**: `songs` フォルダ(実行ファイルの隣・ユーザーデータ内など、曲の置き場)に `.osz` を置くと、約 2〜4 秒後に画面の下に「曲が追加されました: …」と出て、選曲画面なら一覧に加わります(コピーの途中で読まないよう、大きさが 2 回続けて同じになってから知らせます。プレイ中は見張りません。アプリで取り込んだ曲は、知らせません)。
